### Key architectural decisions

| Concern | Decision | Rationale |
|---|---|---|
| API style | REST + versioned (`/api/v1/…`) | Simple, cacheable, easy to scale horizontally |
| Auth | JWT access (15 min) + refresh (7 d) stored in Redis | Stateless API; revocable sessions |
| RBAC | Middleware chain that resolves role → permission matrix | Single source of truth; auditable |
| ORM | Sequelize with migrations | Admin can manage schema via migration runner without raw DDL |
| Bulk ops | Transactional batch inserts/updates via CTE (`INSERT … SELECT`) | Avoids N+1 round-trips; ACID-safe |
| Dynamic fields | `device_fields` metadata table + JSONB column on `devices` | Admin adds/removes columns without downtime; validated at API layer |
| Scalability | Stateless Node cluster behind Nginx; pgBouncer pooling | Add app nodes without session affinity |

> **Best-practice notes baked in throughout:**
> - **Zero raw SQL** — Sequelize parameterised queries everywhere.
> - **Least-privilege RBAC** — permission matrix is a single typed constant; middleware enforces it.
> - **Stateless API** — JWT + Redis refresh tokens → horizontal scaling without session stickiness.
> - **Soft deletes** for users and fields to preserve audit trail and data integrity.
> - **Transactional bulk ops** — one bad row rolls back the entire batch.
> - **Dynamic schema via metadata table + JSONB** — admin can evolve the inventory model without migrations or downtime.
> - **Shared Zod schemas** — one validation source for FE and BE, eliminating drift.
> - **Cursor pagination** — stable under concurrent writes, no `OFFSET` degradation.
> - **Audit logging on every mutation** — satisfies compliance and debugging needs.

This gives you a production-grade, horizontally scalable, and secure foundation that can be iterated on sprint-by-sprint without rework.

### Connection flow (request lifecycle)

1. **Browser → Nginx**: HTTPS request to `/api/*` or static React bundle.
2. **Nginx → Node.js**: Proxied to a cluster of Node.js workers (PM2 or K8s pods).
3. **Node.js → PostgreSQL**: Sequelize/Knex connection pool (SSL, `max: 20` per worker).
4. **Node.js → Redis**: Caching, JWT blacklisting, rate-limit counters.
5. **Admin schema ops**: Admin-only endpoints execute `ALTER TABLE` via a dedicated, audited service (never user-supplied SQL).

## 4. Key Best-Practice Decisions Embedded Above

| Concern | Decision |
|---|---|
| **SQL injection** | Sequelize/Knex parameterized queries only; schema service uses a whitelist DSL, never raw SQL from the client. |
| **Auth** | Short-lived JWT (15 min) + rotating refresh token in httpOnly cookie; Redis blacklist for revocation. |
| **Authorization** | Hierarchical RBAC middleware applied per-route; permissions matrix is a single source of truth in code. |
| **Bulk ops** | Offloaded to a Bull job queue so the API thread never blocks; batched transactions. |
| **Schema changes** | Admin-only, transactional, audited, with dry-run preview. No user-supplied DDL. |
| **Scalability** | Stateless API behind Nginx LB → horizontal scale; PostgreSQL read replica for list queries; Redis for cache & rate-limit. |
| **Observability** | Structured JSON logs, request IDs, Prometheus metrics, audit log table. |
| **Testing** | Unit (Jest), integration (Supertest), E2E (Playwright), load (k6) — all in CI. |
| **Secrets** | `dotenv` locally; environment-injected in Docker/K8s; never committed. |
