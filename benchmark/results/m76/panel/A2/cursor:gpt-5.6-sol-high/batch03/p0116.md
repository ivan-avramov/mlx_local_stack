# Model Parallelism with Sharding Specs in JAX

## Core Concepts

JAX expresses parallelism through three building blocks:

| Concept | Role |
|---|---|
| **`Mesh`** | A named grid of devices, e.g. a 2×2 grid with axes `"model"` and `"data"` |
| **`PartitionSpec`** | Describes *how* a tensor's dimensions map onto mesh axes |
| **`shard_map` / `pjit`** | Tells JAX how to distribute a function's inputs, outputs, and computation |

Model parallelism means you partition **parameters and activations** across devices along the model axis, so no single device holds the full model.

---

## 1. Define a Device Mesh

```python
import jax
import jax.numpy as jnp
from jax.sharding import Mesh, PartitionSpec as P

# 4 devices arranged as 2 (model) × 2 (data)
devices = jax.local_devices()
mesh = Mesh(devices, axis_names=("model", "data"))
```

Each mesh axis is a **logical dimension** you can reference in sharding specs.

---

## 2. Write a Sharded Model

The key idea: annotate every tensor with a `PartitionSpec` that says *which mesh axis splits which tensor dimension*.

```python
import functools

@functools.partial(jax.shard_map, mesh=mesh)
def linear(x, w, b):
    """
    x:  [batch, in_dim]  → split along batch  (data axis)
    w:  [in_dim, out_dim]→ split along in_dim (model axis)
    b:  [out_dim]        → replicated
    """
    # Input sharding
    x = jax.lax.psum(x, axis_name="data")   # not needed here, just illustrative

    # The computation is written as if on a single device.
    # JAX automatically inserts all-reduces / all-gathers where needed.
    y = x @ w + b

    # Output sharding: [batch, out_dim]
    return y
```

In practice you use `pjit` for more ergonomic per-tensor specs:

```python
@jax.pjit(
    in_shardings=[P("data", None),   # x:  [batch, in_dim]
                  P(None, "model"),   # w:  [in_dim, out_dim]
                  P(None)],           # b:  [out_dim]
    out_shardings=P("data", None),   # y:  [batch, out_dim]
    mesh=mesh,
)
def linear(x, w, b):
    return x @ w + b
```

Reading the specs:

- `P("data", None)` → dimension 0 is split across the `"data"` axis; dimension 1 is replicated.
- `P(None, "model")` → dimension 0 replicated; dimension 1 split across `"model"`.
- `P(None)` → single-dim tensor, replicated everywhere.

---

## 3. A Multi-Layer Transformer Block

```python
@jax.pjit(
    in_shardings=[P("data", None),          # hidden_states [B, D]
                  P(None, "model"),          # W_qkv     [D, 3*D]
                  P(None),                   # b_qkv     [3*D]
                  P(None, "model"),          # W_o       [D, D]
                  P(None)],                  # b_o       [D]
    out_shardings=P("data", None),
    mesh=mesh,
)
def transformer_block(h, W_qkv, b_qkv, W_o, b_o):
    qkv = h @ W_qkv + b_qkv          # [B, 3*D]
    q, k, v = jnp.split(qkv, 3, axis=-1)
    # ... attention ...
    attn = (q @ k.T * scale) @ v     # [B, D]
    return attn @ W_o + b_o
```

JAX's compiler inserts the necessary **all-reduces** (for the matmul where one operand is split along the contraction dim) and **all-gathers** automatically. You write the math as if single-device; the sharding annotations are the only parallelism code.

---

## 4. Sharding the Parameters Themselves

Before calling the sharded function, you must place parameters on the right devices:

```python
# Create a full (replicated) parameter dict
params = init_params(key)   # e.g. {"W_qkv": [D, 3D], ...}

# Shard them according to the model axis
sharded_params = jax.tree_util.tree_map(
    lambda p: jax.device_put(p, mesh),   # or use PartitionSpec per tensor
    params,
)
```

More precisely, with `pjit` you can pass a **sharding spec tree** that mirrors the parameter tree:

```python
param_specs = {
    "W_qkv": P(None, "model"),
    "b_qkv": P(None),
    "W_o":   P(None, "model"),
    "b_o":   P(None),
}

sharded_fn = jax.pjit(
    model_fn,
    in_shardings=[P("data", None), param_specs],
    out_shardings=P("data", None),
    mesh=mesh,
)
```

---

## 5. Combining Model + Data Parallelism

The 2D mesh (`"model"` × `"data"`) lets you do both simultaneously. A typical training step:

```python
@jax.pjit(
    in_shardings=[P("data", None), param_specs],
    out_shardings=P("data", None),
    mesh=mesh,
)
def train_step(h, params):
    logits = model(h, params)
    loss = jax.lax.pmean(loss_fn(logits, labels), axis_name="data")
    grads = jax.grad(loss_fn)(h, params)
    return loss, grads
```

- The **model axis** splits weights (model parallelism).
- The **data axis** splits the batch (data parallelism).
- `pmean` over `"data"` synchronises the loss/gradient across data replicas.

---

## 6. The Older `ShardingSpec` API (for reference)

Before `PartitionSpec`, JAX had `jax.sharding_specs.ShardingSpec` with a different (and less ergonomic) interface:

```python
# Old style — mostly deprecated now
from jax.sharding_specs import ShardingSpec

spec = ShardingSpec((
    ShardingSpec.AxisIndex(0, "model"),  # dim 0 → model axis
    ShardingSpec.Replicated(),           # dim 1 → replicated
))
```

Prefer `PartitionSpec` in any new code.

---

## Key Takeaways

1. **Write single-device code.** Sharding is declarative metadata, not imperative partitioning.
2. **The mesh is the vocabulary.** Every `PartitionSpec` references mesh axis *names*, never device indices.
3. **JAX handles the communication.** Matmuls with split contraction dims become all-reduces; pointwise ops stay local. You don't write `all_reduce` calls.
4. **`pjit` is the workhorse** for model-parallel training; `shard_map` is the lower-level primitive when you need finer control (e.g., custom collective patterns).
5. **Verify with `jax.debug.print` or `jax.sharding.get_sharding`** to confirm tensors land where you expect before scaling up.

# Model Parallelism with Sharding Specs in JAX

## Core Concepts

JAX's model parallelism is built on three abstractions:

| Abstraction | Purpose |
|---|---|
| **`Mesh`** | A logical grid of physical devices (e.g., 2×4 of TPUs/GPUs) |
| **`PartitionSpec`** | Describes how each axis of a tensor maps onto mesh axes |
| **`pjit`** | Wraps a function and tells the XLA compiler how to partition it |

The compiler (XLA) then generates a distributed HLO program that places shards on the right devices and inserts the necessary collectives (all-reduce, all-gather, reduce-scatter).

---

## 1. Create a Device Mesh

```python
import jax
import jax.numpy as jnp
from jax.sharding import Mesh, PartitionSpec as P

# Suppose we have 8 devices (e.g., 2 hosts × 4 TPUs)
devices = jax.devices()  # list of physical devices

# Define a 2D mesh: 2 along "data", 4 along "model"
mesh = Mesh(devices, axis_names=("data", "model"))
```

You can reshape `devices` to any factorization. A common layout for a single host with 4 TPUs:

```python
# 4 TPUs on one host → 1×4 mesh
mesh = Mesh(jax.devices(), axis_names=("data", "model"))
```

---

## 2. Define Partition Specs

`PartitionSpec` maps **tensor axes → mesh axes**. An axis left out is replicated.

```python
# A weight matrix of shape [hidden, hidden]
# Split the first dim across "model", replicate along "data"
W_spec = P("model", None)

# An embedding table [vocab, hidden]
emb_spec = P("model", None)

# A batch tensor [batch, hidden]
x_spec = P("data", None)

# A fully replicated tensor
replicated = P()
```

For a 3-D tensor like `[batch, seq, hidden]`:

```python
spec = P("data", None, "model")   # batch split across data, hidden split across model
```

---

## 3. Annotate the Model with `pjit`

```python
import jax
from jax.sharding import Mesh, PartitionSpec as P
from jax.experimental import pjit

mesh = Mesh(jax.devices(), axis_names=("data", "model"))

def model(params, x):
    # params: {"w": [hidden, hidden], "b": [hidden]}
    # x:      [batch, hidden]
    return jnp.dot(x, params["w"]) + params["b"]

# In/out sharding specs
in_specs  = (P(None, "model"),   # params["w"] split along "model"
             P("data", None))    # x split along "data"
out_specs = (P("data", None),)   # output split along "data"

partitioned_model = pjit(
    model,
    in_shardings=in_specs,
    out_shardings=out_specs,
    mesh=mesh,
)
```

When you call `partitioned_model(params, x)`, XLA:
1. Shards `params["w"]` across the 4 "model" devices (each gets `[hidden/4, hidden]`).
2. Shards `x` across the 2 "data" devices (each gets `[batch/2, hidden]`).
3. Computes a **blockwise matmul** locally on each device.
4. All-reduces the partial results along "model" and scatters the final output along "data".

---

## 4. Full Working Example

```python
import jax
import jax.numpy as jnp
from jax.sharding import Mesh, PartitionSpec as P
from jax.experimental import pjit
import functools

# --- Mesh ---
devices = jax.devices()
mesh = Mesh(devices, axis_names=("data", "model"))

# --- Model ---
def linear(params, x):
    return jnp.dot(x, params["w"]) + params["b"]

def transformer_block(params, x):
    x = linear(params["attn"], x)
    x = x + jax.nn.relu(x)
    x = linear(params["ffn"], x)
    return x

# --- Sharding specs ---
# params["attn"]["w"]: [hidden, hidden] → split along "model"
# x: [batch, hidden]  → split along "data"
in_specs  = (P(None, "model"), P("data", None))
out_specs = (P("data", None),)

block = pjit(
    transformer_block,
    in_shardings=in_specs,
    out_shardings=out_specs,
    mesh=mesh,
)

# --- Run ---
hidden, batch = 4096, 128
params = {
    "attn": {"w": jax.random.normal(jax.random.PRNGKey(0), (hidden, hidden)),
             "b": jax.random.normal(jax.random.PRNGKey(1), (hidden,))},
    "ffn":  {"w": jax.random.normal(jax.random.PRNGKey(2), (hidden, hidden)),
             "b": jax.random.normal(jax.random.PRNGKey(3), (hidden,))},
}
x = jax.random.normal(jax.random.PRNGKey(4), (batch, hidden))

y = block(params, x)   # distributed execution
```

## 5. Common Partitioning Patterns

### Tensor (model) parallelism — split a matmul

```python
# Split the contraction dim across "model"
W_spec = P("model", None)   # [hidden/4, hidden] per device
x_spec = P(None, "model")   # [batch, hidden/4] per device
# dot → each device computes a partial [batch, hidden], then all-reduce
```

### Data parallelism — replicate weights, shard batch

```python
W_spec = P()               # fully replicated
x_spec = P("data", None)  # batch split across "data"
# gradient → reduce-scatter along "data"
```

### Pipeline parallelism — split layers

Give each stage its own `pjit` with `P()` (replicated) sharding, and move the activation between stages with explicit `jax.sharding.NamedSharding` on the output.

### Expert / mixture-of-experts parallelism

```python
# experts: [num_experts, hidden, hidden]
expert_spec = P("model", None, None)  # each device holds a subset of experts
```

## 6. Practical Tips

- **`jax.sharding` vs `jax.experimental.sharding`**: The stable API lives in `jax.sharding` (since JAX 0.4.x). `jax.experimental.sharding` is deprecated.
- **`jax.experimental.pjit` vs `jax.jit`**: Use `pjit` when you need explicit sharding control. Plain `jit` lets XLA auto-shard, which is fine for data parallelism but often suboptimal for tensor parallelism.
- **`jax.sharding.NamedSharding`** (or the newer `jax.sharding.Sharding`) can be attached to *values* directly, which is useful when you want to control sharding of intermediate results across multiple `pjit` regions:
  ```python
  sharding = jax.sharding.NamedSharding(mesh, P("model", None))
  w = jax.device_put(w, sharding)
  ```
- **`jax.experimental.shardy`** (older) and **`jax.sharding`** (current) — prefer the latter.
- **Debugging**: `jax.debug.inspect_device_data` and `jax.util.print_sharding` help verify that tensors are where you expect.
- **Flax / Haiku integration**: Both frameworks expose `jax.sharding`-based partitioning via `flax.linen.partitioning` or `jax.sharding` annotations on parameters, so you can write `@jax.sharding.partition`-style decorators on your model.

## TL;DR

1. Build a **`Mesh`** that names your parallelism axes (`"data"`, `"model"`, …).
2. Write a **`PartitionSpec`** for every tensor axis you want to split.
3. Wrap your model (or a sub-module) in **`pjit`** with `in_shardings` / `out_shardings`.
4. Let XLA handle the collective communication; verify with `print_sharding`.

This gives you the same control as hand-written tensor-parallel code, but with JAX's whole-program compilation so the compiler can fuse elementwise ops with the collectives and avoid unnecessary data movement.
