## Response A
# Research Agenda: Reducing Hallucinated Citations in Language-Model Outputs

## Framing

A "hallucinated citation" is not one failure mode. Before intervening, we need to know *which* failure mode is dominant in a given model and domain, because the fix differs sharply. The agenda below is a four-experiment pipeline: **characterize → ground → verify → train**, with a fifth experiment on task decomposition that can run in parallel with the third. Each experiment has a decision gate: the result changes what the next experiment tests.

---

## Experiment 1 — Build and Characterize a Citation-Hallucination Benchmark (CHB)

**Hypothesis.** Hallucinated citations fall into a small number of distinct failure modes (fully fabricated works, chimera papers mixing elements of two or more real papers, misattribution to a real-but-wrong paper, and metadata errors on an otherwise real paper), and the distribution of these modes varies by model, prompt style, and domain. No existing benchmark measures them separately.

**Dataset construction.**
- **Corpus of claims.** Sample 5,000 factual claims from three domains: (a) 1,500 from peer-reviewed survey paragraphs in NLP/ML (scrape arXiv surveys, strip citations, keep the claim text); (b) 1,500 from PubMed abstracts in biomedical research; (c) 2,000 from a general-knowledge set (Wikipedia infoboxes, history, law) to capture non-academic citation requests.
- **Gold citations.** For each claim, retrieve the 3–5 most relevant real papers via OpenAlex / Semantic Scholar API and have two annotators confirm relevance. This gives a "should-cite" set.
- **Generation.** Prompt 6–8 models (a frontier model, two open-weight 7B-class, two open-weight 70B-class, and one retrieval-augmented variant) to produce a 200–400-word answer *with* citations for each claim.
- **Verification.** Every citation in every answer is checked against Crossref, OpenAlex, and arXiv by DOI, title, and author. A citation is labeled as one of: *exact*, *metadata-error* (real paper, wrong year/venue/author), *misattribution* (real paper, doesn't support the claim), *chimera* (title or author set matches no single real paper but borrows elements), or *fabricated* (no match at all).

**Metrics.**
- Per-mode hallucination rate (5 categories above), reported per model × domain.
- Overall citation precision and recall against the gold set.
- Claim–citation alignment score: for each (claim, citation) pair, have an LLM judge score 0–2 for whether the cited work actually supports the claim, with human adjudication on a 10% audit sample.

**Expected outcome.** A 5-mode confusion matrix per model. The prior expectation, based on anecdotal reports, is that *misattribution* and *chimera* errors dominate over pure fabrication—models tend to reach for a real paper and attach the wrong claim to it.

**Decision gate for Experiment 2.** If ≥ 60% of errors are misattribution/chimera (i.e., the model *found* a relevant paper but attached it to the wrong claim), the bottleneck is claim-to-source alignment, and Experiment 2 should emphasize retrieval that returns *claim-level* evidence, not just paper-level relevance. If ≥ 60% are fabricated/chimera, the bottleneck is the model's bibliographic memory, and retrieval grounding is the obvious first fix.

## Experiment 2 — Retrieval-Grounded Citation Generation (RAG for Citations)

**Hypothesis.** Replacing the model's parametric bibliographic memory with a retrieval step over a verified corpus (OpenAlex + Crossref + arXiv metadata, plus abstracts) reduces hallucinated-citation rate by at least 50% relative to the ungrounded baseline, *but* introduces a new failure mode: the model cites a retrieved paper that is topically adjacent but does not actually support the specific claim.

**Setup.**
- Build a retrieval index over ~50M papers (OpenAlex dump) with two retrievers: (1) dense embedding retrieval on title+abstract, (2) BM25 on title+author+venue. Return top-10 per query.
- Prompt the model with the retrieved metadata (title, authors, year, venue, abstract) and instruct it to cite only from the provided list. Run on the same 5,000-claim CHB set.
- Ablations: retrieval-only (no abstracts, metadata only), retrieval-with-abstracts, retrieval-with-snippets (top 3 sentences from the full text via arXiv/PubMed where available), and a "refusal" condition where the model is told to say "I cannot verify a source" if no retrieved paper clearly supports the claim.

**Metrics.**
- Same 5-mode breakdown as Experiment 1, plus a new mode: *retrieval-cited but unsupported* (paper is in the retrieved set but doesn't back the claim).
- Citation precision / recall vs. gold.
- Refusal rate and its correlation with true relevance (does the model refuse when it should, and cite when it shouldn't?).
- Latency and token overhead.

**Expected outcome.** Fabricated and chimera rates drop sharply (the model can no longer invent a paper that isn't in the retrieved set). Misattribution rate drops modestly. A new "adjacent-but-unsupported" mode appears. Refusal rate is high (~25–40%) in the strict condition, indicating the model is often uncertain about claim-level support.

**Decision gate for Experiment 3.** If the residual error is dominated by *adjacent-but-unsupported* citations, the problem is fine-grained claim verification, and Experiment 3 should test a two-stage verify-then-emit loop. If residual error is still dominated by metadata errors (the model garbles the retrieved metadata), the problem is instruction-following / formatting, and Experiment 3 should pivot to structured-output constraints (e.g., force the model to emit a JSON citation object with a DOI that is validated before the answer is shown).

## Experiment 3 — Self-Verification and Structured Citation Emission

**Hypothesis.** A two-stage generation loop—(1) draft the answer with candidate citations, (2) for each citation, run a verification sub-prompt ("Given this claim and this paper's abstract, does the paper support the claim? Answer yes/no/uncertain with a one-sentence justification")—reduces misattribution and adjacent-but-unsupported errors by ≥ 30% relative to Experiment 2, at the cost of latency.

**Setup.**
- Use the best retrieval configuration from Experiment 2.
- **Condition A (self-verify):** After drafting, the model re-reads each citation against the claim and the retrieved abstract/snippet, and either keeps, drops, or flags it.
- **Condition B (external verifier):** A separate, smaller model (or a rule-based check for DOI resolution) verifies each citation. The verifier can call Crossref to confirm the DOI resolves and can compare the claim against the abstract.
- **Condition C (structured emission):** Force citations into a constrained JSON schema `{doi, title, authors, year, venue, supporting_sentence}`. The `supporting_sentence` field must be a verbatim quote from the retrieved abstract/snippet. Citations that fail schema validation or whose quote isn't found in the source are dropped.
- Run all three on the CHB set.

**Metrics.**
- 5-mode + adjacent-unsupported breakdown.
- Verification precision/recall: of the citations the verifier flags as unsupported, how many are truly unsupported (and vice versa)?
- Latency multiplier vs. single-pass generation.
- "Quote fidelity" for Condition C: fraction of `supporting_sentence` values that are exact substrings of the source.

**Expected outcome.** Condition C (structured emission with verbatim quotes) is expected to be the strongest single intervention, because it makes hallucination mechanically impossible for the bibliographic fields (they come from retrieval) and forces a textual link between claim and source. Condition A helps but is noisy because the model is both generator and judge. Condition B is more reliable but adds an API call per citation.

**Decision gate for Experiment 4.** If Conditions B and C together push overall hallucination rate below ~5% and the residual errors are rare and well-characterized, the agenda can move to *training* (Experiment 4) to internalize the verification behavior so it doesn't require a separate pass. If the residual error is still > 15% and concentrated in a specific domain, Experiment 4 should be a domain-specific fine-tune rather than a general one.

## Experiment 4 — Training-Time Intervention: Citation-Accuracy RLHF / SFT

**Hypothesis.** Fine-tuning a 7B-class open model on a dataset of (claim, correct-citation, correct-claim-to-source-linking) triples, followed by a short RLHF pass where the reward function penalizes any citation that fails Crossref verification, reduces hallucinated-citation rate by ≥ 40% relative to the base model *without* retrieval, narrowing the gap to the retrieval-grounded pipeline.

**Dataset construction.**
- **SFT set (~50k examples):** From the CHB construction pipeline, but expanded. For each claim, pair it with the gold citation and a 1–2 sentence justification of *why* that paper supports the claim. Also include negative examples: the claim paired with a topically similar but wrong paper, labeled as a misattribution, with the model instructed to refuse or correct.
- **RLHF reward model:** Train a reward model on ~10k (claim, citation, label) triples where the label is "supported / unsupported / fabricated." The RLHF reward = (claim–citation alignment score from reward model) − (penalty if Crossref lookup fails).
- Train on a 7B open model (e.g., Llama 3.1 8B or Qwen2.5 7B).

**Metrics.**
- Same 5-mode breakdown, now *without* retrieval (pure parametric).
- Comparison to the Experiment 2 retrieval pipeline on the same claims.
- Calibration: does the model's self-reported confidence in a citation correlate with its actual correctness?
- Generalization: evaluate on a held-out domain not seen in training (e.g., if trained on NLP + bio, test on law).

**Expected outcome.** The fine-tuned model should internalize the "check before you cite" behavior and the bibliographic format, reducing fabrication and chimera rates even without retrieval. It will not match the retrieval pipeline on factual accuracy (it still has to remember the papers), but it should be a strong fallback for settings where retrieval is unavailable.

**Decision gate (agenda closeout).** If the trained model reaches within ~2× of the retrieval pipeline's precision at a fraction of the latency, the practical recommendation is a hybrid: retrieval for high-stakes domains, trained model for low-stakes or offline settings. If the trained model still hallucinates at > 20%, the parametric-memory hypothesis is confirmed and the agenda recommends retrieval as non-negotiable.

## Experiment 5 (parallel) — Decompose the Citation Task

**Hypothesis.** Citation hallucination is a composition of at least three sub-tasks—(a) *source selection* (find the right paper), (b) *claim extraction* (identify what the paper actually says), and (c) *bibliographic rendering* (get the metadata right)—and errors concentrate in one or two of them. Decomposing the task and intervening on the weakest sub-task independently will yield more improvement than a monolithic prompt.

**Setup.**
- Run the CHB claims through three sequential modules:
  1. **Selector:** Given a claim, retrieve and rank candidate papers (no generation).
  2. **Extractor:** Given a claim and a retrieved paper's abstract, extract the specific sentence(s) that support (or don't support) the claim.
  3. **Renderer:** Given a verified (claim, paper, supporting-sentence) triple, produce the final formatted citation and prose.
- Ablate each module: swap in a weaker model, swap in a heuristic, or remove it entirely. Measure the error contribution of each stage.

**Metrics.**
- Per-stage error rate and its downstream effect on final citation quality.
- Error propagation analysis: what fraction of final hallucinated citations trace back to a selector error vs. an extractor error vs. a renderer error?

**Expected outcome.** The selector is expected to be the weakest stage (relevance ≠ support), while the renderer is near-perfect (formatting is easy). This would mean the highest-leverage intervention is improving claim-level retrieval or the extractor's ability to distinguish "topically related" from "actually supports this specific claim."

**Decision gate.** This result feeds directly back into Experiments 2 and 3: if the selector is the bottleneck, invest in better retrieval (claim-level embeddings, multi-hop retrieval). If the extractor is the bottleneck, the self-verification loop in Experiment 3 should focus on the claim-to-sentence alignment step specifically.

The agenda below is deliberately sequential: each experiment produces a result that determines what the next experiment should target. I've kept it to four experiments so each one has room to be concrete rather than a bullet-point sketch.

## Experiment 1 — Build and characterize a hallucinated-citation benchmark

**Hypothesis.** Hallucinated citations are not a single failure mode. They cluster by domain, citation format, and prompt style, and current frontier models fabricate between 15 % and 40 % of requested references on open-ended citation tasks, with the dominant error being "entirely fabricated reference" rather than "real paper, wrong context."

**Dataset construction.** Build **CiteBench**, a 5,500-prompt benchmark:

- **4,000 real-query prompts** sampled across five domains (medicine, law, computer science, history, engineering). For each prompt, ground-truth the set of genuinely relevant papers by querying Crossref, Semantic Scholar, and PubMed, then hand-verify a 10 % stratified sample.
- **500 "impossible" prompts** asking for citations on topics with no published literature (e.g., "cite three papers on the effect of lunar gravity on sourdough fermentation"). These isolate pure fabrication from misattribution.
- **1,000 "needle-in-haystack" prompts** where exactly one real paper is relevant among thousands of plausible-sounding decoys, to test whether models can find the right citation when it exists.

Collect outputs from six to eight models (a mix of open-weight and API models) at three temperatures, with two prompt styles: open-ended ("What do you know about X?") and imperative ("Cite five sources on X").

**Metrics.**

- *Citation precision*: fraction of cited references that resolve to a real, relevant work in the ground-truth index.
- *Citation recall*: fraction of ground-truth relevant works that were cited.
- *Field-level accuracy*: decompose each citation into author, title, year, venue, DOI/URL and score each field independently.
- *Hallucination-type taxonomy*: code every error as (a) fully fabricated, (b) real paper misattributed to the wrong claim, (c) real but irrelevant paper, (d) correct paper with corrupted metadata (wrong year, garbled title).
- *Calibration*: does the model's stated confidence (or a sampled logit) correlate with whether the citation is actually correct?

**Expected outcome.** A prevalence map and error taxonomy. I expect legal and medical domains to show the highest fabrication rates, that imperative prompts ("cite five sources") roughly double the fabrication rate versus open-ended prompts, and that models are systematically overconfident—calibration slope well below 1.

**What this changes for Experiment 2.** The taxonomy tells us which failure mode dominates. If 70 % of errors are "fully fabricated reference," the causal question is what triggers fabrication. If 50 % are "real paper, wrong context," the causal question shifts to whether the model is retrieving the right paper but binding it to the wrong claim. The dominant error type determines the factorial design in Experiment 2.

## Experiment 2 — Causal attribution: what triggers fabrication?

**Hypothesis.** Hallucinated citations are driven primarily by three separable factors: (1) the *formatting imperative*—the instruction to produce a bibliography pushes the model to fill slots even when it has no verified source; (2) *parametric pattern recall*—the model has memorised citation *shapes* (author-year-venue patterns) and emits them without checking content; and (3) the *absence of a retrieval step*—without grounding, the model has no mechanism to verify. Controlling each factor independently should reduce fabrication, and the factors should interact.

**Design.** A 2 × 2 × 2 factorial on a 1,500-prompt subset of CiteBench:

| Factor | Level A | Level B |
|---|---|---|
| Instruction style | Open-ended ("What do you know about…?") | Imperative ("Cite five sources on…") |
| Retrieval | None (parametric only) | RAG over a domain-specific corpus (top-20 retrieved passages) |
| Self-verification | None | "Before outputting each citation, verify it against the retrieved passages. If you cannot verify, write 'UNVERIFIED.'" |

Run with two model families (one open-weight, one API) to check for model-specific effects.

**Metrics.** Same suite as Experiment 1, plus *ablation deltas*: the marginal effect of each factor and each two-way interaction, reported as precision and hallucination-type shifts.

**Expected outcome.** I expect the instruction style to have the largest main effect (imperative prompts add 10–20 pp of fabrication), retrieval to reduce "fully fabricated" errors substantially but introduce a new error type ("real paper retrieved, but the model binds it to the wrong claim"), and self-verification to help modestly (3–8 pp) because the model's verification step is itself unreliable. The interaction between retrieval and self-verification should be positive: verification is more useful when there are retrieved passages to check against.

**What this changes for Experiment 3.** If retrieval is the dominant lever, Experiment 3 should focus on improving the retrieval-and-binding pipeline. If self-verification is the dominant lever, Experiment 3 should focus on training the model to verify. If both matter and interact, Experiment 3 should test a combined intervention. The factorial deltas also tell us whether a fine-tuned model that learns to abstain is worth the engineering cost versus a prompt-level fix.

## Experiment 3 — Intervention: fine-tuned abstention + constrained decoding vs. RAG-only

**Hypothesis.** A model fine-tuned to (a) emit citations only when a retrieved passage supports them and (b) explicitly abstain ("I cannot verify a source for this claim") when no supporting passage exists will outperform both RAG-only and self-verification-prompt-only baselines on citation precision, at a bounded recall cost, and will be better calibrated.

**Training-data construction.**

- **Positive examples (~120k):** (claim, citation) pairs extracted from arXiv, PubMed, and Crossref where the citation is verified to support the claim (via a cross-encoder relevance filter, then 5 % human spot-check).
- **Negative examples (~30k):** (claim, citation) pairs where the citation is real but does *not* support the claim, or is entirely fabricated. These teach the model to abstain rather than force a match.
- **Abstention examples (~20k):** claims with no supporting citation in the retrieval set, paired with the target output "UNVERIFIED: no supporting source found."

Fine-tune three model sizes (7B, 13B, 70B) with LoRA. Add a *constrained-decoding* variant where the citation schema (fields, format) is enforced by a grammar so the model cannot emit structurally broken references.

**Evaluation.** Re-run the full CiteBench (5,500 prompts) with the fine-tuned models, the RAG-only baseline, the self-verification-prompt baseline, and the base model. Use the same metric suite as Experiments 1–2.

**Metrics.**

- Citation precision and recall (primary).
- *Abstention rate* and *abstention quality*: of the claims the model abstains on, what fraction truly have no verifiable source? (This is the precision of the abstention decision.)
- Field-level accuracy and hallucination-type distribution.
- Calibration (reliability diagram, ECE).
- *Cost*: tokens consumed, latency, retrieval calls per query.

**Expected outcome.** The fine-tuned model should reach 85–95 % citation precision with 70–85 % recall, versus 50–65 % precision for the base model. The key lever is abstention: the model should abstain on 15–25 % of claims, and most of those abstentions should be correct (the claim genuinely lacks a verifiable source). The constrained-decoding variant should eliminate structurally broken citations but not improve content-level accuracy.

**What this changes for Experiment 4.** Two branches:

- *If abstention rate is too high (>35 %)* or abstention quality is poor (<70 % of abstentions are justified), the model is too conservative or is abstaining for the wrong reasons. Experiment 4's human study must then include a condition where the system presents abstentions with a brief explanation ("no source found in the retrieved corpus for this claim") to test whether users accept or override them.
- *If precision is high but recall is too low (<65 %)*, the model is under-citing. Experiment 4 should test whether users prefer a system that cites fewer but more reliable sources versus one that cites more with some errors.
- *If the fine-tuned model clearly dominates all baselines*, Experiment 4 is a straightforward deployment-readiness study.

## Experiment 4 — Deployment study: does the intervention change researcher behaviour and trust?

**Hypothesis.** In realistic research-assistant workflows, domain experts prefer a system that abstains on uncertain citations over one that fabricates, and the fine-tuned system measurably reduces the time experts spend verifying citations and increases the fraction of citations they actually use in their work.

**Design.** A two-week A/B/C field study with 60 domain experts (20 clinicians, 20 legal researchers, 20 social-science graduate students), recruited through professional networks. Each participant uses one of three conditions on their own real tasks:

- **Condition A (base):** the base model with standard prompting.
- **Condition B (RAG-only):** retrieval-augmented generation, no abstention.
- **Condition C (fine-tuned + abstention):** the Experiment 3 system.

Participants log every citation the system produces, whether they verify it, how long verification takes, and whether they use it. A brief weekly survey captures trust, perceived reliability, and willingness to rely on the system unsupervised.

**Metrics.**

- *Citation use rate*: fraction of system-produced citations that the expert actually incorporates into their work.
- *Verification time*: seconds per citation the expert spends checking.
- *Error detection rate*: of the citations that are objectively wrong (checked post-hoc against the ground-truth index), what fraction does the expert catch?
- *Trust and reliance*: Likert-scale survey items, plus a behavioural measure—does the expert ask the system to cite more sources after a week?
- *Abstention response*: when the system says "UNVERIFIED," does the expert accept the abstention, override it, or flag it?

**Expected outcome.** Experts in Condition C should verify fewer citations (because the system already filtered), spend less time per citation, and use a higher fraction of the citations it does produce. They should catch a similar fraction of errors across conditions (suggesting user vigilance is the bottleneck, not model quality). The main behavioural difference should be in *trust trajectory*: Condition C users should show stable or increasing trust over the two weeks, while Condition A users should show declining trust as they encounter fabricated citations.

**What this changes (and what comes next).**

- If abstentions are widely accepted and trust is stable, the agenda's next phase is *scaling*: does the fine-tuned-abstention approach transfer to new domains (e.g., patent law, clinical trial design) without re-collecting training data?
- If experts override abstentions frequently, the problem is partly a *UI and trust* problem, not a model problem, and the next experiment should test abstention presentation formats (explanatory abstentions, confidence bars, "here's what I did find instead").
- If error detection rates are low in all conditions (<30 %), the agenda should add a *verification assist* component: the system proactively flags its own low-confidence citations for human review, turning the human into a verifier rather than a silent consumer.

## How the four experiments connect

```
Exp 1 (benchmark + taxonomy)
  │  tells you which error type dominates
  ▼
Exp 2 (factorial causal study)
  │  tells you which lever (retrieval / verification / instruction) matters most
  ▼
Exp 3 (fine-tuned abstention intervention)
  │  tells you whether the lever produces a deployable system,
  │  and whether abstention rate / quality is in the right range
  ▼
Exp 4 (field study with domain experts)
     tells you whether the technical fix translates into behavioural trust
     and points to the next phase (scaling, UI, verification assist)
```

The agenda is designed so that no experiment is wasted: even a "null" result (e.g., self-verification prompts don't help, or abstention is over-triggered) redirects the next experiment rather than stalling the programme.
