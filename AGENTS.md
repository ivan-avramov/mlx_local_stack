# mlx_local_stack

Local stack: mlx_vlm task model (port 8092), mlx-serve main models (port 8000), and OpenWebUI on docker compose (port 3000).

Terse rules live HERE; full rationale, measurements and sagas live in the pointed-to docs. When
a rule here and a doc disagree, this file wins and the doc needs a dated correction.

## Slash commands

- `/mlx start` — runs `./runserver.sh` (syncs submodules, backs up OWUI data, launches both model servers, brings up compose, tails logs; Ctrl+C tears down via the trap).

## Entry points & logs

- `runserver.sh` (full bring-up; reads `.env` for `HF_TOKEN`), `main_models.yaml` (mlx-serve registry), `openwebui_config.json` (seeded each start), `do_backup.py`.
- Logs: `logs/{mlx_vlm,task_model,main_model,compose}.log`.

## Client/agent integrations (configs we ship)

Five clients, all pointed at the mlx-serve router (`localhost:8000`, OpenAI-compatible):

| config | client | class |
|---|---|---|
| `opencode_config/opencode.json` | opencode CLI — **primary agentic harness** | full-sampling |
| `aider_config/` | aider — **RETIRED as a harness 2026-08-16** (rows kept, no new arms; `benchmark/run_aider_docker.sh` frozen) | full-sampling |
| `openwebui-init/models_config.json` | OpenWebUI (:3000) — SOURCE OF TRUTH, pushed by `publish_models.py`/`init.py` (NOT the DB-export `openwebui_config.json`) | full-sampling |
| `vscode_config/chatLanguageModels.json` | VS Code — Copilot Chat BYOK + Roo Code | registration-only |
| `zed_config/settings.snippet.jsonc` | Zed editor assistant | registration-only |

- **full-sampling** carriers hold the complete per-model sampling (temp, top_p, top_k, min_p, presence_penalty, max_tokens, enable_thinking, thinking_budget). **registration-only** carriers declare model+context+capabilities; they get the tuned config via the registry's `generation_defaults` (FU-2, 2026-07-09: mlx-serve forwards per-model defaults, applied only when a request omits a field — see `docs/serving-path.md`).
- **A per-model sampling/thinking change must hit ALL FOUR carriers**: `opencode_config/opencode.json`, `aider_config/aider.model.settings.yml`, `openwebui-init/models_config.json` (then `publish_models.py`), AND `main_models.yaml` `generation_defaults`. Then audit for drift. A new model/context/capability change touches all five configs + the registry.
- `kv_prealloc_tokens` is **structural** (registry→worker only, not a client carrier). **Set equal to that model's `max_kv_cache_size` — the full-cap prealloc rule STANDS (operator 2026-08-14); do not remove or lower it** (realloc double-buffer measurably OOMed). Do not cite peak-memory from short-generation probes for anything memory-related (O15). Full saga: `docs/serving-path.md`.
- **`max_kv_cache_size` is OUTPUT-DETERMINING and part of the provenance fingerprint** (it sets the resolved thinking budget). Runs at different caps never pool; check the cap of existing rows before resuming any arm — `--clean-stale` deletes across a cap change.

## Mission & priorities

- Goal: evidence-based pick of a local LLM for 256K-context agentic coding on a 64GB Mac, plus transferable methodology for future H200/B200 work. Phase 1 = Selection, Phase 2 = Optimization. Bias QUALITY over speed/cost.
- Hard gates: memory ≤46GB MLX-peak @256K (metric = `mx.get_peak_memory`, prefill spike, NOT RSS). Every lossy lever ≤5% quality drop, measured OFAT. Effective-context threshold = accuracy ≥0.85; retrieval-depth and reasoning-depth curves stay SEPARATE. Report prefill-TTFT and decode-tok/s separately.
- For every result, LOG THE BOTTLENECK/MECHANISM. Verdicts are HW-specific; mechanisms transfer.
- **`docs/PLAN.md` is authoritative for what is live.** Current summary (2026-08-31): B menu (C38) — 1st `Qwen3.6-27B-Opus-Distill-OptiQ-4bit` (M6b), 2nd `Ornith-1.0-35B-mlx-uniform-4bit` (M27), 3rd `Qwen3.8-27B-mlx-uniform-4bit` (M6d; leads every pooled coding cell, nothing Holm-surviving) — all three are CERTIFIED (model, tune, mtp-predictor) triples; C has provisional picks (O38).

## Operating rules

- **`main_models.yaml` IS THE REGISTRY OF RECORD for the campaign's picks** (operator 2026-08-23): always the current B and C 1st/2nd choices at certified params, updated in the SAME commit as any certification or pick change (`# CERTIFIED <milestone> <date>` notes in `generation_defaults`). Every pick must be publicly downloadable from HF, with a **`caslca/<full-registry-name>` insurance clone**; promote local-only checkpoints by uploading FIRST. Provisional picks are allowed, labelled PROVISIONAL. **A pick ships as a (model, tune, predictor) triple**: predictor certified by PLAN M6d recorded as registry `draft_kind` + params; until then draft-OFF. Measurement is ALWAYS predictor-OFF. The committed file stays PII-free (a not-yet-uploaded checkpoint commits as the `caslca/` placeholder + NOT-YET-UPLOADED note).
- **ONE resident model per machine, always.** Unload between models: `POST /v1/models/unload` + `pkill -f bench.run_*`.
- **SINGLE BOX since 2026-08-17: the M5 Max 64GB is driver AND worker.** All older two-box (M2 Max / M4 Pro driver / remote M5) language in docs is historical; those procedures — including GIT-ONLY-TRANSPORT and the ssh traps — are archived in `docs/two-box-archive.md` and become live again only if a second box returns.
- Router (re)start: `cd <repo> && set -a; . ./.env 2>/dev/null; set +a; MLX_VLM_CACHE_SESSION_MAX=2 MLX_SERVE_CONFIG=main_models.yaml nohup uv run mlx-serve start >logs/main_model.log 2>&1 </dev/null &` → :8000. Lean router (no OWUI/docker) for benchmarking. **`MLX_VLM_CACHE_SESSION_MAX=2` is MANDATORY, not optional** (2026-08-23: without it the fork defaults to 8 retained sessions; anonymous single-turn benchmark traffic then preallocs ~4GB KV per item-session → 55GB worker → swap). After a crash the router may report a model "ready" with no live subprocess → 500s; restart to clear.
- **Every benchmark run is REPORTED AND CRITICALLY EVALUATED every 5 minutes** (operator 2026-08-13) — by a DAEMON (`benchmark/m1/bench_watch.py` or equivalent alongside every run), never by conversational intent. Each assessment answers: (1) progressing? (item counter vs its own past, never worker busyness); (2) rate vs prediction? (ETA from the MEAN — right-tailed distributions make median ETAs flatter by ~40%); (3) output sane? (errors, convergence, `nonconv_kinds`, completion-token distribution incl. degenerate-EOS); (4) needs correction, and is correcting cheaper than finishing? Findings go in the run log.
- Monitoring mechanics: foreground `sleep` is blocked; launch long runs detached (`nohup … </dev/null &`), poll from a background waiter. Never infer a job stopped — `pgrep`/kill BY PID.
- **NO FILESYSTEM POLLUTION OUTSIDE `$STACK_WORKDIR`** (operator 2026-08-17): every out-of-repo artifact lives under it (see `config.sh`). Pre-approved exceptions: `~/.cache/huggingface`, `~/.cache/livecodebench`, uv/venv caches, `$TMPDIR/mlx-manager-logs`. Third-party tools' DEFAULT paths are the escape hatch (nltk re-created `~/nltk_data` when `NLTK_DATA` was unset) — VERIFY redirecting env vars are in the process env before launching anything that writes; a tool with no redirecting knob is a blocker to raise.
- **No PII in the repo — it is PUBLIC.** No absolute home paths, hostnames, usernames, tokens, emails — in content OR history. Machine-local values live in `${XDG_CONFIG_HOME:-$HOME/.config}/mlx_local_stack/config.sh`; committed files use placeholders (`$STACK_REPO`, `$STACK_WORKDIR`, …). The pre-commit `bench.piicheck` guards staged lines; if PII reaches history, `git filter-repo --replace-text` + force-push.
- Edit the PARENT forks, not the `src/*` submodules: `../mlx-vlm`, `../mlx-serve`. Flow: edit fork → commit → push fork → bump submodule in the stack → `git submodule update --force`. Test forks via `PYTHONPATH=../mlx-vlm …`.
- Propose before fixing/committing/pushing; an approved plan does not cover newly found bugs. Commit/push only when asked; **never `git push` without explicit in-turn approval**. Write commit messages from `git diff --staged`.
- TDD for features/bugfixes: failing test first, watch it fail, minimal code to pass.
- Bench tooling: lazy-import heavy deps, graceful-degrade (`skipped/acc:null` + note, never crash the batch), mocked in tests. Venv facts: `docs/box-notes.md`.
- Commit prefixes: `chore(stack): bump src/mlx-vlm -> <sha> (<summary>)`, `feat(bench)`/`fix`/`docs`/`data(bench)`.
- **Docs registry:** `docs/PLAN.md` = the backlog (authoritative); `docs/work-queue.json` = only what has been ATTEMPTED (never call it the backlog); `docs/handoff.md` = THE one handoff, rewritten in place each session; `docs/open-questions.md` = operator decision queue (add items the MOMENT a judgement call is identified; never delete closed items); `docs/campaign-results.md` = living results record; `docs/lab-notebook.md` = history; `docs/regrade-vs-rerun-guideline.md`, `docs/metrics.md`, `docs/serving-path.md`, `docs/box-notes.md`, `docs/two-box-archive.md` = moved rationale.

## Measurement discipline (READ before any A/B — full derivations in `docs/metrics.md`)

- **THINKING IS ENABLED FOR ALL TESTS** — never disabled to "make a benchmark work". A budget-hit is a FAIL signal to INVESTIGATE, never fixed by lowering the budget. `converged = (finish_reason=="stop" AND completion_tokens < thinking_budget)`; `finish=="stop"` alone is a FALSE PASS.
- **Judge convergence against the RESOLVED budget**: the fork silently clamps `thinking_budget = min(budget, int(min(max_tokens, cap−prompt) * 0.8))`. The harness corrects at one seam (`convergence.resolved_thinking_budget`, mirrors the fork's 0.8 — keep in step). Before spending worker time: a run whose `max_tokens` exceeds `cap − prompt` measures a budget you did not choose. Never quote "% of budget" without naming which budget.
- **The thinking budget is EXTERNAL TRUNCATION, not a model knob** — set generous fixed headroom (e.g. 81920), never tune it; never compare runs differing only in budget. **The knob for non-convergence is TEMPERATURE** — run the standing temperature-ladder recipe (coarse OFAT 0.7→0.5→0.3, pass@1 the hard constraint, convergence secondary; capped fine scan for runaway items; per-model, never globalized). Full recipe: `docs/metrics.md`.
- **APPLES-TO-APPLES IS MANDATORY**: same box, same session, same config; re-measure baselines alongside tests. Record box+config+params with every result.
- **When results contradict published rankings, suspect OUR HARNESS FIRST.** Inspect raw outputs; near-zero accuracy means template/mode/parse mismatch. Match each model's intended eval MODE (native FC for tool-calling; generous token caps).
- Production params verbatim via `bench/model_params.py:params_for(model, profile="deployed")` — `deployed` reads `main_models.yaml` `generation_defaults` and is the profile for ALL new axes (`production` has DRIFTED and measures a different serving path; kept only for old rows). **Every `run.py generate` carries `--sampling-profile deployed` explicitly (O36).** Vary ONLY the param under test.
- **Convergence is a VECTOR, scored per item**: report `(acc, acc_strict@budget, conv%, nonconv_kinds)`. **`acc_strict@<budget>` IS THE RANKING KEY at a MATCHED budget** (DNF counts in the denominator; `compare.py` refuses cross-budget). `pass@1|converged` is DEMOTED to a DIAGNOSTIC and must NEVER rank (denominator conditioning). No composite metrics; report the FOUR numbers — capability ceiling + exclusive-solve sets, edit competence, latency per task, runaway tax (rate + wall-clock share) — and never rank on `successes_per_hour` (refuted; `docs/metrics.md`). Code-quality beyond execution belongs to the judge panel (built, NEVER RUN) — don't let `acc` stand in for it.
- **ITEMS BUY POWER; SAMPLES BUY RELIABILITY.** MDE (paired, α=.05, .80): N=15→±32pp, N=40→±20pp, N=100→±12.5pp, N=164→±9.8pp, N=378→±6.4pp. Never print a delta without its interval and the axis MDE; "inconclusive" is a valid answer (TOST ±5pp for `equivalent`); Holm across metric families. Intervals from the two-stage cluster bootstrap (`stats.cluster_bootstrap`), never pooled Wilson.
- **Every draw carries an explicit seed** (`rowschema.sample_seed`): unseeded requests are BYTE-IDENTICAL copies (k unseeded samples = k copies) — WITHIN a server session; cross-restart determinism is NOT guaranteed (measured 2026-08-23, `docs/metrics.md` seeds section). Seeds derive from (item, sample) → paired across models.
- **Every bench DRIVER launch carries `MLX_SERVE_CONFIG=<the served overlay>` in its env (C35, bit twice: 2026-08-26, 2026-09-01)** — `paths.registry_path()` reads it for the fingerprint; without it manifests record the registry-of-record's `draft_kind: mtp` while the worker verifiably serves draft-OFF, and the tripwire only catches the model whose worker is live at precheck. Verify on the driver pid (`ps -Eww`); check the first manifest's `runtime.draft_kind` + `registry.sha256` before the second item. False-provenance rows are archived and regenerated, never graded.
- **APC IS OFF EVERYWHERE** (benchmarks AND daily driver). Start routers with `APC_ENABLED` absent and VERIFY on router + worker pids (`ps -Eww`) — a stale export silently persists. Session caching shadows APC by construction; the session cache is what makes multi-turn cheap. Guarded by `test_provenance_fingerprint.py::test_runserver_does_NOT_enable_apc`; mechanism + OOM history: `docs/serving-path.md`.
- **FULL registry model names everywhere** — reports, results, docs, commits, AND CHAT PROSE; first use in every message and commit body. Banned shorthands include bare `Nemotron`, `Ornith`, `the distill`, `gemma`, `the MoE`, `the OptiQ`, `qat-6bit`, `8bit`. <!-- allow-shorthand --> Disambiguate arch + bit-width when comparing. Enforcement: `githooks/` pre-commit + commit-msg run `bench.modelnames` on ADDED lines and the message (install: `git config core.hooksPath githooks`) — the hook CANNOT see chat prose; that part is behavioral. `<!-- allow-shorthand -->` marks lines that must show a banned form.
- Capacity metric = `mx.get_peak_memory` (prefill spike); keep the box quiet during capacity runs.
- Instrument by axis: recall/reasoning → exact-match; code correctness → execution-gated; subjective quality → blind mixed-family judge panel over execution-PASSING outputs only. Start every real benchmark with a `--limit 5` smoke.
- Two-phase harness (`benchmark/`): `generate` (slow, resumable) → `grade` (fast, mechanical), over HTTP against :8000; `--order roundrobin`. Grading recipes (EvalPlus docker, LiveCodeBench, BFCL entry points): `docs/box-notes.md` + `benchmark/README.md`.
- **RE-GRADE vs RE-BENCHMARK is a decision RULE**: `docs/regrade-vs-rerun-guideline.md`. Re-grade is free; re-run only what re-grading provably cannot recover.

## Known pitfalls (one-liners; histories in the pointed docs)

- **Speculative decoding (suffix/MTP/draft) is inherently non-lossless on bf16** — proven, don't re-chase as "bugs". **Suffix is OFF for all models** (2026-08-16); `draft_kind` is populated in fingerprint v3 and `compare` REFUSES across differing draft state (quality AND speed). Verify at the worker cmdline (`ps -o command=`), never from the yaml alone. Return condition O25. Full saga: `docs/serving-path.md`.
- **Penalties and suffix decoding are mutually exclusive per request** (`_suffix_structured_fallback`): any nonzero penalty/logit_bias/structured output → plain decode. `presence_penalty 0.0` is load-bearing while suffix is ON. `compare` refuses across penalty mismatch.
- **`presence_penalty` is NOT the fix for runaways** (measured NO-GO: context_size 20 cannot reach 40–262-token cycles; degenerate loops cost TIME not accuracy). The lever is TEMPERATURE.
- `prefill_step_size` must be threaded into generation, else 2048 default → 4× QK² scratch → 256K OOM. EpiCacheKVCache is single-sequence only.
- Quant sensitivity is real, not architectural (recall can differ across quants of the same model). Converted/MTP-packaged quants need loader tolerance.
- M5 Neural Accelerators are ACTIVE by default (mlx ≥ 0.31.2 wheel, macOS ≥ 26.2, GPU gen ≥ 17): 3.8× fp16 GEMM / 3.5× 4-bit qmm vs the forced non-NA path (`MLX_METAL_GPU_ARCH=applegpu_g16s` is the control). Never judge NA by an fp16/fp32 ratio — fp32 GEMM is accelerated too. Prefill numbers already include it (corrected 2026-08-31; the June "dead end" was an instrument error).
- 🚨 **NO JOB AT n≥40 ENTERS THE QUEUE WITHOUT A 5-ITEM PILOT, drawn as a SEEDED RANDOM SAMPLE across the corpus — never the first items** (they are ordered easy-first; a first-items pilot under-sized M18 by 2.5×). **Size from the pilot's MEAN and MAX, treat the estimate as a LOWER BOUND, and budget known heavy-tail mechanisms (runaways, multi-function items) explicitly on top** — n=5 fixes the bias, not the variance. Cost estimates were optimistically wrong five times; the tail IS the measurement.
- 🚨 **`timeout` does not exist on macOS** (nor gtimeout). Write runners in Python with real subprocess timeouts, or bound with `--probe-timeout`.
- **`rc=$?` inside `if ! cmd; then` is always 0** — use `set +e; cmd; RC=$?; set -e`. **`| tail` masks failures in `&&` chains** — redirect to a file and check `$?`. **zsh does not word-split unquoted variables.** **Never `|| true` in a queue entry** (it laundered a fake BFCL smoke).
- **`pkill -f` does not reliably kill the router** — force-kill by PID and verify 0 listeners on :8000.
- 🚨 **Client timeouts are DERIVED (max generation ÷ floor decode rate + headroom, retries=0), never SDK defaults** — the OpenAI default (600 s, 2 retries) is shorter than a legitimate full-budget generation on every pick; it converts budget-hits into error rows graded as wrong answers. **Transport/HTTP failures ESCALATE (abort, nonzero exit), they are NEVER graded**; the worker does not cancel abandoned requests, so a client that times out and retries multiplies worker load and starves neighbours. A silent-but-BUSY worker is a runaway (do not kill); silent-and-IDLE is a wedge (kill by PID). Saga: `docs/lab-notebook.md` 2026-08-24, O41.
- **Never change serving config during a live run**; verify a flag LANDED via the worker's `ps -o command=`.
- **Validate an instrument against a known-positive before trusting a zero.** A monitor that cannot distinguish "healthy" from "not looking" is worse than none.
- **Never report from a run prefix**; verify elapsed time from `ps -o etime`, not memory.
- Registry/serving config facts (FU-2 resolved-sampling readback must use a value that DIFFERS from the registry default; worker stdout goes to DEVNULL), conversion/quant-family identification hazards, corpus provenance facts (sha split, polyglot metadata, contamination controls, `session_pass` vs `final`, IFEval verifier quirk, derived max prompt), and box administration (TCC, Jamf, snapshots, docker grading image): **`docs/box-notes.md`** and **`docs/serving-path.md`**.
