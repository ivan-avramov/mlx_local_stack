## The change (decision C119)
`benchmark/bench/generate.py` is the generation loop of the benchmark harness (`run.py generate` → `generate.run`). Until now one broad `except Exception` turned EVERY per-item exception except `ServedConfigError` into an "error row" and continued with the next item. Project rule (AGENTS.md): "HTTP/transport errors abort nonzero, never grade"; "Transport failures must abort"; retries = 0. Two rulings constrain the fix: O35 — a client timeout that ran to ≥ 0.9 × the configured probe timeout is a DNF row with `error_kind: "probe_timeout"`, counted as done on resume (a seeded retry reproduces the runaway); O31 — error rows count as failures in `acc_strict` at grade time. The design and its rationale are in `docs/proposal-transport-abort.md` (sections P126, P127, P130 — the `generate` half only; the opencode-probe half is out of scope).

Intended behaviour: fail-closed allowlist. `ServedConfigError` → re-raised as before. A client timeout whose elapsed time classifies as `probe_timeout` → the DNF row, run continues. Everything else (connection refused/reset, non-timeout `URLError`, any `HTTPError`, `RemoteDisconnected`, `MalformedResponseError`, an EARLY timeout, any harness exception such as `KeyError`) → raise `client.TransportAbort` chained from the original; no row for the in-flight item; no further request; every manifest of the run stamped `transport_abort: {item, sample, bench, model, error (scrubbed, ≤200 chars), elapsed_s, rows_on_disk, ts, served_check}`; a previous stamp is kept under `transport_abort_history`; a preload failure aborts the same way; `run.py generate` exits nonzero. Legacy error rows without `error_kind` keep their treatment (retryable on resume).

The diff: `git diff -- benchmark/bench/generate.py benchmark/bench/client.py benchmark/README.md` plus the new untracked file `benchmark/bench/tests/test_generate_transport_abort.py`. Ignore `docs/open-questions.md` and `ts.md`.
