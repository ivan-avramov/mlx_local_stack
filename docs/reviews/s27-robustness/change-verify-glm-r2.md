**Minor finding (M1):** `stage_failure` (`tg2_grade.py:1505`) classifies a stage failure as `GraderInfraError(kind="spawn")` only when `rc == 125 AND not timed_out`. A docker spawn that times out (the container failing to start within the deadline) is left untyped, so it is not regraded. This is a defensible reading of §5.1 ("a grader TIMEOUT … is the item's OUTCOME"), and distinguishing a spawn-timeout from a stage-script timeout is hard since both carry `timed_out=True`. Not a defect under the spec, but a real docker-daemon-loss-during-spawn that times out would be scored as the model's outcome rather than regraded. Severity: minor (the spec's closed list names "container spawn failure" as infra, and this narrows it to non-timeout spawn failures).

- **Location:** `benchmark/bench/tg2_grade.py:1505-1510` (`stage_failure`).
- **Severity:** minor.
- **Evidence:** confirmed (traced in source).
- **Problem:** A `docker run` that fails with rc=125 and `timed_out=True` is not typed as a grader infrastructure fault, so it is not regraded; it is the item's outcome.
- **Failure scenario:** Docker daemon becomes unresponsive mid-spawn; `docker run` is killed by the harness timeout, returning rc=125 with `timed_out=True`. `stage_failure` returns a plain `TransportAbort`; the item is scored as a model failure rather than regraded.
- **Proposed change:** Treat `rc == 125` as spawn-infra regardless of `timed_out` (a docker-run rc=125 is the daemon's own failure status, not the stage script's). If the concern is agent-caused stage timeouts, gate on `rc` alone for the spawn classification and leave the `timed_out` gate for other rc values.
