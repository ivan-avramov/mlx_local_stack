If the operator later picks "as tg1", the sequencer and signals must change. The spec doesn't say the implementer should build the seam now (parameterised) or defer.
**Failure scenario:** A transport DNF occurs in a tg2 decider leg; with no make-up, it's a strict 0 (C343 (3)) — which is the spec's intent. But if the operator picks "as tg1" later, the leg table has no make-up legs and the sequencer can't run them.
**Proposed change:** State that the implementer builds the no-make-up path now (Q1 default), with the make-up seam left as a documented extension point; or pick Q1 now.

## Scope requests

**S1.** A tg2-specific `p426_freeze cmd_v8` / `write_amendment` path (B1): the spec implies `p426_freeze` gains a tg2 mode, but the existing freeze is deeply tg1-shaped (rehearsal, R1/R2/R3, historical walls). Building a parallel tg2 freeze is a substantial new surface the spec doesn't detail. Request: scope this as a named build step with its own interfaces, or confirm the operator writes the freeze and the sequencer only reads it (the candidate's punt).

**S2.** The C331 (3) pre-decider nuisance re-check (B6): if it can change α, it is a new `m76_sim` invocation wired into the sequencer with a new output; if it is diagnostic, it still needs a function and a screen-rows reader. Request: scope the re-check as a build step or confirm it is diagnostic-only.

**S3.** Run-time injected positives for tg2 (B7): parameterising the `arm_runner` inject path (out dir, addenda source) by corpus touches a tg1 code path. Request: confirm this is in scope (the spec lists `arm_runner.py` as changed), or drop the run-time inject for tg2 and rely on grader known-positives only.

## What the acceptance criteria should test but do not

**A1.** The tg2 freeze round-trip: write a tg2 v8 base + amendment from a synthetic smoke pair, then verify every tg2 leg accepts the amendment (walls present and numeric, `deadline_formula` over rust/javascript/java/cpp). The criteria test "the walls check" but not the freeze→leg acceptance round-trip (B1).

**A2.** The per-language HOLD through the full signals path: a synthetic B8 where one language's decider point is −22.5 pp must produce `hold.blocking = True` and a `kv_flags` entry. The criteria mention "HOLD at −20 / −22.5 pp" but not that it flows through `axis_verdict(..., languages=...)` and into `flags` (B4).

**A3.** A tg2 leg with a transport DNF in a decider session: the DNF slot is strict 0, the leg is `VALID_WITH_DNF`, B8 accepts, and the signals score it 0. The criteria test "DNF = 0" but not the DNF→B8→signals path end-to-end (C343 (3)).

**A4.** The harvest of a real tg2 grade tree that includes every docker bookkeeping tag (`plan-*`, `volume-*`, `own-*`, `holder`, `own-holder`, `<step>-pre`, `-n`, `-rm`, `-v`, `-x`, `cl-holder`, `cl-*`, `rm-*`, `ls-*`), not just the step files. The criteria say "fixture recorded from one real grade per language" but don't assert the fixture exercises every tag (B8).

**A5.** `verify_a8_kv` reading from `wave2-tg2/` (not `wave2/`): a synthetic tg2 tree under `m76/wave2-tg2/` is verified, and one under `m76/wave2/` is refused. The criteria don't pin the wave directory (B5).

**A6.** tg1 byte-identical with a tg2 v8 base + amendment present in the same record dir: the tg1 golden (plan, argv, rows, B8, signals) is unchanged when a tg2 freeze is written beside it. The criteria test "tg1 byte-identical" but not with tg2 records coexisting.

**A7.** The `GradeOutcome.outcome == "model"` invariant for every tg2 graded outcome, including `storage_cap` with `grader_oom=False`. The criteria test "the grader mapping per outcome" but don't assert the `outcome` field value and the resource flags for `storage_cap` specifically (B9, B10).
