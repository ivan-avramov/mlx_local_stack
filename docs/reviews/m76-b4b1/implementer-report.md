## Deviations from the spec, with the code fact that forced each
1. **Universe verification.** The spec names `bench/tg2_universe.py`; the module is `m65/tg2_universe.py`. Its `load()` refuses the committed universe on the baseline (`freezer_sha256` differs; I changed none of its closure members). `Tg2Corpus.load_universe` therefore checks the recorded facts instead: sidecar sha, the pin, grader and materializer versions, image id, and polyglot sha.
2. **Normalised view omits Rust `Cargo.lock` files outside the prepared tree.** `tg2_grade`'s tamper check flags any new `Cargo.lock` (only `src/*.rs` may be added), so a plain `cargo test` would make the item tampered. The grader's compile step deletes and regenerates every lock anyway.
3. **`bench/modelnames.py` changed** (outside the scope list): `test_model_name_check` requires every configgen target to be in `GENERATED_PATHS`, and the spec says so too.
4. **`validate_reports` tg2 rules are opt-in** (`grader="tg2"`, passed by `validate_leg` / `inject_verify` for the tg2 scaffold): the existing M64 four-language fake corpus (see above). Every non-tampered tg2 receipt must carry `phases.json`, my analogue of tg1's "launch outputs".
5. **H5 rule limited to tg2 item directories:** the frozen P586/P587 tests assert other `.grades/` files stay unclassified.
6. **`--evidence` expression shape** forced by the source-text test in `test_b2_s4_reconcile`.
7. **`--tg2-inject` is argparse dest `tg1_inject`:** the shared core reads a single inject attribute.
8. **`run_tg2_chain` imports `chains.c147.run_tg1_chain`** to reuse its KV after-load checks, record checks and ops builders. Its chain closure therefore includes the tg1 chain module.
9. **Rehearsal directory is `$STACK_WORKDIR/m76/p426/rehearsal.tg2/`** (the spec's path is a placeholder). `--out-root` must lie strictly below it, which is tg1's existing rule.
10. **Re-check 2 runs after the reload pair**, following the spec's order line; the spec's text says "after s2". Both pool s1 + s2 rows.
11. **Re-checks are sealed to `<out-base>/run/recheck-<gate>.json`.** The sequencer reads `positives.json` from `--record-dir`, so the record directory must be the run directory that holds it.
12. **The tg2 docker gate checks both `aider-benchmark` and `tg2-grader`:** `toolchain.current()` also needs `aider-benchmark`.
13. **`t_coop` for tg2 uses join = 2 × max(grader_timeout_s) + 60.** tg1's constant 660 is that same formula over tg1's table.
14. **Positives order:** the stub / reference grades run before the serving session (no GPU needed).
15. **v8 base record fields.** The tg2 v8 base also records `rehearsal_receipts` and `tg2_image_id`. Its `pilot_deadline_s` is `fz.TG2_PILOT_DEADLINE_S` (6 h, tested equal to `REHEARSAL_DEADLINE_S`) because of an import direction.
16. **Default-argument guards** keep tg1's calls unchanged: `default_hooks` gets `inject_lang` only when it is not `"go"`, and the helpers get the corpus argument only for tg2. Tests stand in for these functions.
17. **tg1 golden composite comparison.** The fake client binary embeds tmp paths, so its sha varies per run. The golden therefore compares the generation composite with the exe sha fixed. It also drops the volatile row fields (paths with run ids, times, evidence shas, worker, termination).
