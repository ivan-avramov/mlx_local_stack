P1 — Location: Projection, spec.md:94–98. Severity: major. Evidence: confirmed. Problem: `PICK_BASELINE["prefill_s"]` is seconds, while every `TIMING` and append value is milliseconds; the formula omits `/1000`. Concrete failure: `fixed` becomes hundreds of thousands of “seconds” negative at 260K, yet the native check still passes tautologically. Proposed change: divide both summed attention and append terms by 1000, preferably via the existing `prefill_attn_total_s()` helper.

P2 — Location: Projection, spec.md:94–98; context_probe_report_excerpt.py:60–73. Severity: minor. Evidence: confirmed. Problem: “clamped at the ends” contradicts the existing projection’s linear extrapolation below the first checkpoint. “Long-context” append means no specific checkpoint/pass aggregation, and the native reconstruction check validates nothing because `fixed` is defined to make it true. Concrete failure: conforming implementations produce different projections, especially for early chunks or by selecting the anomalous cap append value. Proposed change: name the exact interpolation function and append source, e.g. two-pass mean at T=260096; replace the tautological check with a unit test against hand-computed synthetic data.

P3 — Location: Reuse, A4 and timing design, spec.md:56–57, 73–83, 108, 121. Severity: major. Evidence: confirmed against MLX 0.32.4 allocator source. Problem: the fixed-T test and `peak-active_before` omit cached buffers. MLX tracks cache memory separately, and its cache cannot reuse a smaller buffer for the next 512-token-larger scratch. Timed repetitions therefore reuse an exact-size warm buffer, while real prefill allocates larger K/V buffers each chunk and retains prior ones until garbage collection. Concrete failure: A4 passes near 1 GiB and checkpoint timings look fast, while a 260K prefill accumulates many stale scratch sizes, incurs allocation/GC stalls, and loses the intended memory saving. Proposed change: either produce cap-sized scratch buffers and slice them to T, or add a growing-T chunk test that records `active + cache` memory and allocation-inclusive timing.

P4 — Location: A4 window, spec.md:81–83, 108. Severity: major. Evidence: confirmed. Problem: MLX is lazy, but the window does not require `mx.eval`/synchronization or define output lifetimes. “One graph per call” also does not model the dependent graph of successive model layers. Concrete failure: sixteen calls merely construct graphs, `peak-active_before` remains near zero, and A4 passes without executing the kernel. Alternatively, individually evaluated calls pass while a single model graph retains several scratches. Proposed change: pre-evaluate inputs, reset counters, chain 16 calls through the query output, evaluate and synchronize the final output, then read peak/cache memory. Optionally also test individually evaluated calls and use the worse result.

P5 — Location: A1 and its fp32 reference, spec.md:79–80, 102–104. Severity: major. Evidence: hypothesis; the supplied report confirms only P1-versus-production error, not P1-versus-fp32. Problem: P1’s bf16 materialization may exceed `2 × max(production error, 2⁻¹²)`. If so, a perfectly bit-identical implementation cannot satisfy A1. Concrete failure: implementation completes and matches `rot_fused()` exactly but fails the accuracy gate, with no permitted numerical repair. Proposed change: preflight `rot_fused()` itself against the proposed fp32 reference at every checkpoint before implementation; pre-register a revised existing-path tolerance if it fails.

P6 — Location: Exactness sweep, checkpoint procedure and JSON, spec.md:70–87, 102–103; probe excerpt:202–213; cache state excerpt:374–385. Severity: minor. Evidence: confirmed. Problem: `deq_rot()` is a closure with no T argument and consumes state sliced to `cache.offset`; the sweep does not state that offset equals each T. A1 also requires checkpoint dequant identity, but the procedure/schema records only whole-path identity there. Concrete failure: the reference has cap-sized output while the kernel has T-sized output, or the report declares A1 without checkpoint dequant evidence. Proposed change: define reference helpers taking an explicit state/T, state that each sweep cache has `offset=T`, and add checkpoint K/V identity fields—or restrict dequant identity to the sweep.

P7 — Location: Negative control and sampled accuracy heads, spec.md:70–80, 105. Severity: minor. Evidence: hypothesis. Problem: “each KV head scaled differently” does not specify amplitudes, T or L sufficient to guarantee failure of the loose A1 tolerance. Heads `{0,11,23}` exercise KV heads 0, 1 and 3, omitting KV head 2. Concrete failure: N1 differs bitwise but still passes `allclose`, or a head-2-specific indexing defect escapes the fp32 check. Proposed change: use planted, widely separated constant values per KV head with fixed T/L, and sample one query head from each group, e.g. `{0,6,12,18}`.

P8 — Location: Goal, Interfaces and A1, spec.md:14–18, 54–64, 102–104. Scope request. Evidence: confirmed. Problem: full-path bit identity and mandatory fp32 multiplication exceed the operator’s settled accuracy requirement and can reject faster numerics that remain within tolerance. Concrete failure: a half-product or otherwise optimized kernel meets the requested accuracy and speed goal but is rejected solely for non-identical bf16 bits. Proposed change: keep dequant bit identity as a diagnostic or baseline-fidelity check, make accuracy the acceptance gate, and reduce full-path identity to one representative test—or explicitly obtain operator agreement that bit identity is a new constraint.

P9 — Location: Reuse/A4 naming and smoke criterion, spec.md:57, 81, 108–111. Severity: minor. Evidence: confirmed. Problem: the memory window is repeatedly called A5 although A5 is the in-place criterion. `--max-t 32768` is also undefined relative to the fixed T=40000 exactness row and T=262144 memory window. Concrete failure: the smoke unexpectedly allocates the full-cap state or records the wrong criterion as skipped/passed. Proposed change: rename the window A4 and specify exactly which sweep rows and memory checks `--max-t` suppresses.
