## Not satisfied or worth knowing
- **A4 receipt shape:** it was not available, so `a4_window_problems` assumes `receipt["anon"]["requests"]` and `receipt["opencode"]["requests"]` as lists, falling back to 3 and 4. Check this against the real `a4_v2_latest.json`.
- **Settle bound:** the chain uses `P426_SETTLE_BOUND_S = 900.0` unless `args.settle_bound_s` is set. The v8-base value (max of 900 s and 2× the largest request) belongs to the later freeze slice.
- **Test coverage:**
  - No chain-level test of "abort before `.ready` → systemic". `dnf_problems` with no ready record is tested, and eligibility turning any `dnf_problems` result into a refusal is tested with a stub, but the two are not joined.
  - No end-to-end test of a DNF on the fake probe, or of an ON-arm run; the e2e tests cover only OFF-arm reconciled items and an invalidate.
  - The `--evidence p426` argv test checks the `build_cmd` call site by source inspection. The existing s2 test (chain launches every invocation with `--evidence p426`) also covers it end to end.
- **Pre-existing behaviour:** after an `invalidate` at `done`, I saw `CHAIN ABORT: web evidence is immutable: export.web.jsonl exists` in one run's log. I did not investigate it; the leg still ended rc 2 with `p426_invalid` recorded.
- **`log_bounds.json` extras:** it carries a `problems` list when a log was replaced, beyond the §16.1 schema. Absent log files are created empty at open so their identity is fixed before the router appends. The real `start_router` uses `>logs/main_model.log` per AGENTS.md; that truncates the same inode, which my finalize check reports as truncated if the file's size drops below its start offset. Verify this against the real router start before the first live leg.
- **Router identity in the ready record:** `owned.router` is `{pid, start}` from the new `ChainOps.router_identity()`, and is `null` when the ops object lacks that method.
