## 3. Gaps (unnamed or ambiguous)

- **G1, the frozen record (§1, §2, §10.1): this blocks every chain-level `--p426` test.** The rehearsal manifest, v8 base and timeout amendment have no schema (kind field, self-hash field), and `p426_freeze` has no named arguments. Yet s1 must already refuse "a record of the wrong kind". I recommend the operator name the record schema, or a `main(…, records=…)` seam, before delivery 2.
- **G2, after-load seams (§6.3–6.4).** The ops methods for process environments, the interpreter / `RECORD` inventory, `vmmap`/`lsof` and snapshot hashing are unnamed. Even with G1 solved, fake ops cannot pass this checkpoint without them.
- **G3, how the chain finds `<WT>/logs/mlx_vlm.log` and reads `/metrics` (§4.1; s4 adds "metrics / log access" to `chain_ops`).** Unnamed.
- **G4, module APIs.** Functions and classes are unnamed in `p426_reconcile` (equalities, settle, the §8 decode estimator), `p426_hooks`, `p426_receipt`, `p426_secrets`, `p426_wave2` (argv per leg, deadlines §10.2, make-up grouping §5.5), and the arguments of `p426_freeze` / `p426_wave2`.
- **G5, record fields.** No field names are given for:
  - the ready record, item record and `p426_dnf` record;
  - `log_bounds.json`, `HARVEST.json`, the leg record and the pair dossier;
  - the watcher receipt line and its destination (§8; I used `--out`);
  - the `<slot>` spelling in `items/<slot>.*` (slot keys contain `|`).
- **G6, the P426 constructor keyword (§2, §13 "`OpencodeArm(mode="tg1", p426)`").** I used `p426=True`.
- **G7, abort-manifest placement (§2 [r3]).** Where the session id, in-flight message id and termination go is unnamed. I assert `cause`, `gate.request_usage`, a `termination` key, and that the session id appears somewhere in the stamp.
- **G8, the §4.1 pairing fixture.** The P456 rehearsal row + log slice is not committed. From C225's "completion / prompt tokens", I assumed `request_usage[1]` ↔ `generated_tokens` and `[2]` ↔ `prompt_tokens`.
- **G9, `SCRUB_MANIFEST.json` is not on `main`.** The operator-email refusal and the P437 scrub rules (§11.3) have nothing to test against.
- **G10, harvest destinations (§11.2).** The evidence-stage location and the root for `main` destinations are unnamed. I assumed the repo root that contains the bench package.
- **G11, refusal text.** My refusal tests require the output to name the offending flag or file. The spec only says "refuse".
- **G12, PRED_S retirement (C221).** The "recorded generic default" (value and location) is unnamed, so there is no test.
- **G13, legacy `schedule_sha256` (§2).** It isn't observable for the legacy argv, because tg1 doesn't freeze its schedule. Legacy goldens are therefore pinned by probe invocation order; the schedule sha is pinned only in s0 via `schedules.tg1(...)`.
- **G14, the watcher exit at baseline.** My watcher test calls the real `pmset -g log` at exit, because no seam is named. It is read-only, but not fully hermetic.
- **G15, s0 is baseline-shaped.** Four s0 tests run legacy argv without `--models`, and s0 calls `schedules.tg1(...)` with the base signature. Once s1 lands (C221 makes `--models` required), these will fail. The operator needs to decide whether s0 is retired or converted at that point.

## 4. Possible errors or contradictions in the spec

1. **§14.5 vs C236.** §14.5 says "no change to production serving code (fork / mlx-serve)", but C236 makes B2 run on S′, which bumps the gitlinks. My s0 identity test pins the base gitlinks, so it fails if S′ is merged into the B2 branch.
2. **§7 / §1 pilot "as today".** The P426 pilot is "the first 5 of s1's Python order", where the order is `Random(1001).sample(sorted(pool), 22)`. Today's pilot phase is `sorted(Random(1001).sample(pool, 5))`. CPython's `sample` uses different algorithms for k=5 and k=22 on a pool of 22, so the two item sets generally differ. "As today" is ambiguous.
3. **§4.3, `completed_unaccounted`.** "C equals `request_usage` in count and order" is stated unconditionally. The table's `completed_unaccounted` row (one trailing C line absent from `request_usage`) contradicts it unless the table overrides.
4. **§8, 1-token requests.** The spec calls their `D` "negligible". But the fork's `_decode_elapsed_from_metrics` falls back to `generated_tokens / generation_tps` when there are fewer than 2 token times. A 1-token request's `D` is therefore one token-interval, not zero.
5. **§3 / §6.7, the probe argv.** The manifest checkpoint requires `TG1_P426_EVIDENCE`, but the common flags and the probe argv never state that the chain passes `--evidence p426` to the probe.
6. **§1 R1 vs §2.** R1 is "smoke shape (1 + 2)", while §2 refuses `--smoke` in P426 mode. How `--rehearsal` selects that shape is unstated.
7. **§13 wording.** "s2's first language is Go at the probe's `--items`": the language travels in `--lang`; `--items` carries bare names.
