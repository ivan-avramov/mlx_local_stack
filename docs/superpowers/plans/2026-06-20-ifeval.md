# IFEval (Instruction-Following) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add IFEval (programmatic instruction-following) to the generate→grade pipeline, scored by the official google-research verifiers (vendored), reporting prompt-/instruction-level strict & loose accuracy with prompt-level-strict as the headline.

**Architecture:** IFEval is a single-shot, objective benchmark with NO model judge — each instruction has a deterministic verifier (`keyword count`, `JSON format`, `N bullets`, …). We **vendor** the official `instruction_following_eval` modules (Apache-2.0, pinned commit) under their original package name on `sys.path`, and call their `evaluation_lib.test_instruction_following_strict/loose` directly so we reproduce the paper's numbers rather than reimplement ~25 verifiers. Generation reuses the existing chunked/resumable loop (the prompt *is* the instruction); grading re-loads the `google/IFEval` dataset to recover each item's `instruction_id_list`/`kwargs`, builds `InputExample`s, runs the verifiers, and aggregates. The verifier deps are heavy/optional → lazy-imported with graceful degradation (same discipline as `grade_lcb`/`grade_evalplus`).

**Tech Stack:** Python 3 stdlib + `datasets` (already a project dep) for the IFEval dataset; the vendored `instruction_following_eval` (deps: `absl-py`, `langdetect`, `nltk` + punkt, `immutabledict`) installed only where grading runs. pytest for tests, mocking the vendored verifiers.

## Global Constraints

- **Vendor the OFFICIAL verifiers, pinned.** Source: `google-research/google-research/instruction_following_eval` at commit **`5b09c22d73a9d35eb6c5d2a99b95677a45053466`** (2026-02-09, Apache-2.0). Vendor the 4 interdependent modules **verbatim** — `instructions.py`, `instructions_registry.py`, `instructions_util.py`, `evaluation_lib.py` — under the package name `instruction_following_eval` (they use absolute imports `from instruction_following_eval import ...`, so the package name must be preserved and its parent dir put on `sys.path`). Record the commit in a NOTICE file. Do NOT hand-reimplement verifiers.
- **Verifier deps are optional + lazy-imported.** `grade_ifeval` must degrade gracefully (`acc: None` + `note`) when the vendored package or its deps (`absl-py`/`langdetect`/`nltk`/`immutabledict`) are missing — never crash the grade batch.
- **None-filter the dataset kwargs.** The HF `google/IFEval` rows pad every `kwargs` dict with all-possible-keys = `None` (a schema artifact). The verifiers' `build_description(**kwargs)` breaks on `None` args. EACH per-instruction kwargs dict MUST be filtered to non-None entries before use.
- **Programmatic grading, NO model judge.** The verifiers are the oracle (this is instruction-following, not subjective quality). The judge panel (a later sub-plan) never touches IFEval.
- **Report all four IFEval metrics**, headline = prompt-level strict: `prompt_strict` (fraction of prompts following ALL their instructions), `inst_strict` (fraction of individual instructions followed), `prompt_loose`, `inst_loose`. `acc` = `prompt_strict`.
- **Grade by re-loading the dataset + joining on id** (id = the dataset `key`), mirroring `grade_lcb` — generation only saves `{id, content, …}`, so the instruction metadata is recovered at grade time. The subsample limit/seed don't matter for grading; load the full dataset and join.
- **`evaluation_lib` API (verified upstream 2026-06-20):** `InputExample(key:int, instruction_id_list:list[str], prompt:str, kwargs:list[dict])`; `test_instruction_following_strict(inp, prompt_to_response) -> OutputExample`; `test_instruction_following_loose(inp, prompt_to_response) -> OutputExample`; `OutputExample` has `.follow_all_instructions: bool` and `.follow_instruction_list: list[bool]`. Response is read as `prompt_to_response[inp.prompt]`.
- **Run-time-validated boundary (don't over-test):** the real vendored verifiers (which need the 4 deps + `nltk punkt`) are validated on the first real grade run where deps are installed. Unit tests cover the pure logic (item-shaping + None-filter + metric aggregation + graceful-degrade), mocking `evaluation_lib`.
- **Tests run from `benchmark/`:** `cd benchmark && uv run --with pytest --with psutil python -m pytest bench/tests/`.
- **First-party `benchmark/` code only** (the vendored dir is first-party-checked-in third-party code with attribution).

```python
# ----------------------------------------------------------------- instruction-following loader
def _ifeval_item(row: dict) -> dict:
    """Shape one google/IFEval row -> harness item. The HF schema pads every kwargs dict
    with all-possible-keys = None; the verifiers' build_description breaks on None, so each
    per-instruction kwargs dict is filtered to its non-None entries."""
    kwargs = [{k: v for k, v in (kw or {}).items() if v is not None} for kw in row["kwargs"]]
    return {"id": row["key"], "prompt": row["prompt"],
            "meta": {"instruction_id_list": list(row["instruction_id_list"]), "kwargs": kwargs}}


def _load_ifeval(limit, seed):
    from datasets import load_dataset
    ds = load_dataset("google/IFEval", split="train")
    items = [_ifeval_item(row) for row in ds]
    return _subsample(items, limit, seed)
```

```python
def _load_ifeval_lib():
    """Lazy-import the vendored IFEval verifiers. Adds bench/vendor to sys.path so the
    package's absolute imports (`from instruction_following_eval import ...`) resolve, and
    best-effort ensures the nltk 'punkt' tokenizer the verifiers need. Raises if the deps
    (absl-py/langdetect/nltk/immutabledict) are absent — the caller degrades gracefully."""
    import os
    import sys
    vendor = os.path.join(os.path.dirname(__file__), "vendor")
    if vendor not in sys.path:
        sys.path.insert(0, vendor)
    from instruction_following_eval import evaluation_lib  # noqa: E402 — heavy optional deps
    try:
        import nltk
        try:
            nltk.data.find("tokenizers/punkt")
        except LookupError:
            nltk.download("punkt", quiet=True)
    except Exception:  # noqa: BLE001 — tokenizer is best-effort; verifiers that need it will fail closed
        pass
    return evaluation_lib


def _ifeval_aggregate(strict_outs, loose_outs) -> dict:
    """Prompt-level = fraction of prompts following ALL their instructions; instruction-level
    = fraction of individual instructions followed. Computed for strict and loose verdicts."""
    def prompt_acc(outs):
        return (sum(1 for o in outs if o.follow_all_instructions) / len(outs)) if outs else 0.0

    def inst_acc(outs):
        flat = [b for o in outs for b in o.follow_instruction_list]
        return (sum(1 for b in flat if b) / len(flat)) if flat else 0.0

    return {
        "prompt_strict": round(prompt_acc(strict_outs), 4),
        "inst_strict": round(inst_acc(strict_outs), 4),
        "prompt_loose": round(prompt_acc(loose_outs), 4),
        "inst_loose": round(inst_acc(loose_outs), 4),
    }


def grade_ifeval(name, model):
    """Grade IFEval with the vendored official verifiers (lazy, graceful-degrade). Re-loads
    the IFEval dataset to recover per-item instruction_id_list/kwargs, runs strict+loose, and
    aggregates. Headline acc = prompt-level strict."""
    rows = [r for r in _rows(model, name) if not r.get("error")]
    if not rows:
        return {"benchmark": name, "model": model, "n": 0, "acc": None, "note": "no completions"}
    try:
        ev = _load_ifeval_lib()
    except Exception as e:  # noqa: BLE001 — optional verifier deps
        return {"benchmark": name, "model": model, "n": len(rows), "acc": None,
                "note": f"ifeval verifiers unavailable ({type(e).__name__}: {str(e)[:80]}); "
                        f"install benchmark/requirements.txt where grade runs"}
    meta_by_id = {it["id"]: it for it in benchmarks.load("ifeval", None, 0)}
    strict_outs, loose_outs, graded = [], [], 0
    for r in rows:
        it = meta_by_id.get(r.get("id"))
        if it is None:
            continue
        inp = ev.InputExample(key=it["id"], instruction_id_list=it["meta"]["instruction_id_list"],
                              prompt=it["prompt"], kwargs=it["meta"]["kwargs"])
        p2r = {it["prompt"]: r.get("content", "")}
        try:
            s_out = ev.test_instruction_following_strict(inp, p2r)
            l_out = ev.test_instruction_following_loose(inp, p2r)
        except Exception:  # noqa: BLE001 — a single verifier blowing up shouldn't kill the batch
            continue
        strict_outs.append(s_out)   # append BOTH only after both succeed, so the
        loose_outs.append(l_out)    # strict/loose lists stay index-aligned
        graded += 1
    if not graded:
        return {"benchmark": name, "model": model, "n": 0, "acc": None,
                "note": "no rows matched the IFEval dataset"}
    agg = _ifeval_aggregate(strict_outs, loose_outs)
    return {"benchmark": name, "model": model, "n": graded, "acc": agg["prompt_strict"], **agg}
```
