## 1. What is actually established about suffix decoding

**Theory.** Draft-then-verify speculative decoding with correct rejection sampling is
**distribution-preserving in exact arithmetic**. It is lossless *in distribution*, never
token-identical. In finite precision the verification step evaluates a **batch** of drafted positions
rather than one at a time; different reduction orders shift logits slightly and flip the sampled
token on near-ties. That is numerics, not a logic bug.

**Measured on this stack** (`bench/probe_determinism.py`, `Ornith-1.0-35B-mlx-uniform-4bit`, M5, one
session, APC absent, temp 0.4, 3 reps/cell, sha256 of reasoning+content, suffix toggled in the
registry with a router restart and **verified at the worker cmdline**):

| | truncation ON (0.95 / 20 — deployed) | truncation OFF (1.0 / 0 / 0.0) |
|---|---|---|
| **suffix ON** | byte-identical ×3 (ct 2,364) | **DIVERGENT 3/3** (ct 2,825 / 4,467 / 3,736) |
| **suffix OFF** | byte-identical ×3 (ct 2,318) | byte-identical ×3 (ct 3,127) |

- Suffix is the source of nondeterminism; tail truncation **masks** it. Unclipped: 1.6× length spread.
- **ON and OFF are different fixed points** — different text at the same truncated config, each
  internally reproducible. Truncation makes suffix-ON self-consistent; it does NOT make it equal to
  suffix-OFF.
- The "quality-neutral" claim is an **aggregate** one (he+/mbpp+/LCB within noise) at MDEs of ±12.5pp
  (n=100) and ±32pp (n=15). The campaign's own gate for a lossy lever is **≤5%**, which needs **628
  matched items**. **The gate has never been demonstrated for suffix.**
- Latency benefit is real: **23.8 s vs 30.3 s = 1.27×** on a novel coding prompt, same box/session.
- Recorded mechanism: suffix **accelerates verbatim repetition** (2.41× verbatim / 1.09× novel).
  Degeneracy is already large in the corpus (`Ornith-1.0-35B-mlx-uniform-4bit`: 4 degenerate items,
  **40%** of humanevalplus and **63%** of mbppplus wall-clock), and whether suffix contributes is
  **unmeasured**. Not a claim — a testable mechanism aimed at a known weak spot.

⚠️ **`AGENTS.md` line ~164 says "Campaign runs suffix-OFF". That is FALSE and must be fixed** — it is
ON for both winners. It also cannot simply be inverted to "runs suffix-ON", because the state is
per-model (§0).

## 4. Traps that cost time this session — do not re-learn these

1. **`timeout` does not exist on macOS** (nor `gtimeout`, nor coreutils). An unguarded `timeout ...`
   fails "command not found", which under `if ! cmd` is indistinguishable from the job failing: a
   runner "completed" 110 items in under a second. **Write runners in Python** — subprocess timeouts,
   real exit codes, JSON output. All three bugs in the bash runner were shell-specific.
2. **`rc=$?` inside `if ! cmd; then` is always 0.** Use `set +e; cmd; RC=$?; set -e`.
3. **`opencode run` needs `--dir`; subprocess `cwd` does not set its project root.** Without it the
   probe wrote into the stack repo and reported `file_changed=False` — which would have read as "the
   model cannot edit" when the log showed it editing and self-verifying successfully.
4. **Validate an instrument against a known-positive before trusting a zero.** A watcher's glob was
   wrong by two directory levels and would have reported a false stall on a healthy run; `pip show`
   printed nothing because these uv venvs have **no `pip`** (import name is `optiq` — a python package, not a model <!-- allow-shorthand -->; both boxes carry
   mlx-optiq **0.4.21**).
5. **Never report from a run prefix.** "Temperature falsified" was called off 2 items and the 3rd
   contradicted it; a mean of 26.6 s at 120 items was 29.4 s at 200.
6. **The models can rewrite the test file.** Observed. A modified test invalidates the grade and is
   now scored as a failure.
7. **`.meta/` holds the reference solution** — exclude it from any scratch copy.
8. **Model names:** full registry names in prose *and* commit messages. A pre-commit hook
   (`githooks/`, allowlist derived from the registry) now blocks added lines and commit messages, but
   it cannot catch semantic references ("the fast one"), and chat prose is never committed. It caught
   the author repeatedly.

### Phase H — harness
- Grade all five languages **inside the `aider-benchmark` container** (opencode edits on the host).
  Re-grade the 4 existing python opencode rows in-container for consistency.
- Add `opencode` to `ROLES["coding"]` in the scoreboard; demote `aider` to a diagnostic column.
- Freeze the aider runners with a header (no new arms; kept to reproduce the 110 rows).
- **Progress-gated bound** for opencode sessions, replacing a fixed timeout. Every 300 s: snapshot the
  workdir to a copy (never race a live write), grade it, record
  `(solution_hash, n_failing_tests, repeated_tool_call_signature)`. Progress = failures decreased, or
  the file changed without failures increasing → continue past the soft budget. Two consecutive flat
  ticks → stop (stall). Same signature 3× → stop (loop). Hard ceiling as backstop only. Record
  `stop_reason ∈ {completed, stalled, looping, hard_ceiling}`, the failure trajectory, tick count and
  the effective bound. **The policy must be IDENTICAL across models** — the dynamic part buys early
  exit on stalls, never extra compute for a favoured model, else pass rates encode compute.
- Score the **session outcome** (`session_pass`), not intermediates. Explicitly NOT comparable to
  aider's `final`, which allows a second test-informed attempt.
- BFCL vendored handler: post raw `messages` + `tools` to `/v1/chat/completions` under our served
  names. It is the only proxy for Zed, which has no headless mode. `bfcl_eval` 2026.3.23 is installed
  on the **worker only**, despite AGENTS.md claiming both boxes.
