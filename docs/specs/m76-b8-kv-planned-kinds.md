## Fixes

- **F1 (C355 (2), K7) — rule 2d compares per-arm facts per arm.** In `kv_provenance` (and every kv rule-2d comparison):
  1. Each string leaf has the arm's OWN worktree component normalised (`_kv_path_re(arm)` → `m76-q-ARM` / `m76-f45-ARM`) before the
     cross-arm comparison; a leaf naming another arm's worktree is a rule-2d reason. Content hashes beside paths (e.g.
     `runtime.corpus_sha256`) stay compared across arms.
  2. `result_file` / `result_sha256` leave the cross-arm comparison. Per arm they are integrity: `result_file` == the basename of
     the result file B8 read for that arm (item) and `result_sha256` == sha256 of the bytes B8 read (`provenance.result_digest`
     semantics); absent or unequal → a rule-2d reason naming the arm.
- **F2 (C355 (2), K3, K4) — `compute_kv` reads the record's completeness.** `wave1.dropped` kinds report `status: "not_run"` with
  `ruling` (M1: never `missing`). Any planned pair (`p426_plan.kv_w1_kinds(build)` × b1, b2) rejected or absent → one blocking flag
  `wave1_incomplete` per pair (`member` = `"<kind>/<label>"`, `text` = the first reasons). Tier-2 `not_run` blocks are not flagged.
- **F3 (C355 (3), S25-P1, K8) — the A5 counter renders the served template.** `offline_counter` passes the entry's deployed
  template kwargs (`params_for(entry, profile="deployed")`: `enable_thinking`, `reasoning_effort`, each only when set — the
  server's `to_template_kwargs` semantics) to every `apply_chat_template` call, calibration included; meta gains
  `template_kwargs`. Regenerate `benchmark/results/m76/ids.json` with its generator (`python -m bench.m76_ids`, from `benchmark/`)
  and write `IDS_CHANGES.md`: old / new ids.json sha256, old / new chars-per-token, old / new count and resolved budgets per rung,
  reason (C355 (3), S25-P1). The diff of ids.json is confined to `axes.longctx.budget`, `budget_inputs.{prompt_tokens,counter}` and the derived `prompt_deviation` (erratum v1.1a).
- **F4 (K2, K5; erratum v1.1a)** — `verify_all_kv(..., kinds=None, build="s3")` keeps `kinds` (subsets for tests and fixtures; 18 existing
  tests use it); `None` = the planned kinds and the CLI never passes another set; `dropped` is recorded either way. K2's hazard (an incomplete
  planned wave reading clean) is closed at the consumer by F2: every planned pair absent from the record is a blocking `wave1_incomplete`.
- **F5 (K6)** — `KV_W1_KINDS` lives in `p426_plan`; `p426_verify` imports it (one definition).
- **K1** — test-only (`test_m76_b3_impl_wave1::test_main_kv_refuses_v…` passes `--axes m1` in its `n16,x` half): the
  test-writer's delivery 3, not the implementer.

## §v1 (2026-11-16, unchanged where not overridden)

### Goal

Stage 3a's readout needs B8 (`bench.p426_verify all --lever kv --pair n16,x`) to verify the harvested Wave 1 of build `s3` and emit
its record for the signals. Today it cannot: `verify_wave1_kv` loops every `KV_W1_KINDS` kind including `m1` and indexes
`m76/ids.json[kind]`, which has no `m1` (a qualify leg has no items) → `KeyError`; and a missing tier-1 leg refuses, so with M1 dropped
from stage 3a (C352) B8 would refuse forever. Solving it means: B8 verifies exactly the kinds the stage planned, records every
unplanned kind as `not_run` with its ruling, still refuses any missing leg of a planned kind, and never indexes `ids` for a kind
without items — the mtp lever and every other B8 behaviour unchanged.

### Scope

`benchmark/bench/p426_plan.py` (the planned kinds), `benchmark/bench/p426_verify.py` (`verify_wave1_kv`, `verify_all_kv`),
`benchmark/bench/p426_wave1.py` (the kv sequencer's default `--axes`); tests `benchmark/bench/tests/test_m76_b8_kinds_*.py`. Read-only:
`benchmark/results/m76/ids.json`, `bench/m76_ids.py`, `bench/p426_signals.py` (v1.1: no longer read-only, see Scope above).

### Interfaces

- `p426_plan.kv_w1_kinds(build) -> tuple` and `p426_plan.kv_w1_dropped(build) -> dict[kind, reason]`: for `s3`, kinds
  `("math500","cjudge","vision","reasoning","longctx")` and dropped `{"m1": "C352: M1 dropped from stage 3a (stage 1's matrix certifies
  memory)"}`; any other kv build → `KV_W1_KINDS`, nothing dropped; an unknown build refuses.
- `verify_all_kv(rows_root, repo, pair, kinds=None, build="s3")` (v1.1 F4: no `kinds`): the record's `wave1.not_run` lists each
  dropped kind's blocks as `"<kind>/<label>"` and a new `wave1.dropped = {kind: reason}`.
- `verify_wave1_kv`: indexes `ids[kind]` only for kinds that have items in `ids.json`; a kind with no items (`m1`) is verified from its
  leg evidence as today, never through `ids`; a missing leg of a planned kind still refuses (no verdict on incomplete evidence).
- `p426_wave1 --lever kv`: the default `--axes` is `kv_w1_kinds(build)`.

### Acceptance (v1)

1. Red first, on the REAL committed `benchmark/results/m76/ids.json` (no mocked ids): today's `verify_wave1_kv` with the default kinds
   raises `KeyError` / refuses on a synthetic harvested s3 tree with every planned leg and no m1 legs; after: the record verifies, lists
   `m1/b1`, `m1/b2` in `not_run`, `dropped.m1` with the reason; a missing planned leg (e.g. `cjudge … b2`) still refuses; an explicit
   `kinds=` including `m1` with m1 legs present still verifies them; the mtp lever's B8 golden unchanged.
2. (Designer) the public CLI over the real harvested stage-3a Wave 1 emits B8 and the signals run on it.
3. The stack suite passes or fails only as on the baseline.
