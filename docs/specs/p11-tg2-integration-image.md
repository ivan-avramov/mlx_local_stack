# P11 — Select a verified image for live tg2 integration tests

The historical tg2 image and its base are absent from this machine's Docker stores. The committed context reproduces byte for byte at the stamp commit. A grader rebuilt from that context on the existing base passed all 15 offline acceptance cases and the 44 affected live Docker integration cases in a disposable comparison. Run the existing Docker integration cases in the standard stack gate with an explicit, verified local image without altering historical grading inputs.

Add test support module `bench.tests.tg2_docker_image` exporting `configured_image() -> str | None`. Read `MLX_STACK_TG2_TEST_IMAGE`. Unset returns None without Docker or file access. When set, require a full lowercase `sha256:<64 hex>` image ID, including rejecting empty input. Inspect that ID locally via Docker, with a short bounded timeout. Require the actual reported image ID and labels `tg2.version=m65-v1`, `tg2.polyglot_sha` and `tg2.context_sha256` to match the committed image record metadata. Missing expected metadata, missing image, invalid response, daemon failure and wrong labels must fail loudly as RuntimeError for an opted-in override, with a useful message. Test it by patching the process seam. No lookup by a mutable tag and no pulls.

Use the configured ID only in the real Docker integrations in `test_tg2_grade.py`, `test_tg2_grade_timeout_fe_docker.py`, `test_tg2_grade_timeout_impl_docker.py` and `test_tg2_grade_timeout_impl_regrade.py`. The existing availability test inspects the designated ID. Pass it for both `image_id` and `image_tag` at the grading boundary, including the existing child-process case, and use it on direct Docker commands that read the default ID today. Reuse one set of helper values and preserve the exact default archived image/tag path when unset. Keep unit/mock tests, grader limits, offline execution, original assertions, recorded benchmark artifacts, `IMAGE_ID`, production code, and the gate policy and skip baseline intact.

Acceptance: all 44 existing integration cases run and pass with the explicit local image; default unconfigured behavior remains the existing historical-image check; refusal and selection unit cases pass without Docker. The actual release gate must still run the complete suite against the exact final stack commit. Record the selected image and source fingerprints alongside the stack gate run.
