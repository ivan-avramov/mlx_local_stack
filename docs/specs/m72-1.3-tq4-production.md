# Spec: M72 1.3 — production build of the whole TQ4 attention path (C317; cold design review → Go → four-eyes strict)

Status: v1 draft, 2026-11-10 (session 21), not reviewed. Designer: the session. Records: `docs/open-questions.md` C312–C317,
S20-P13 / P14 / P18; prototypes and their specs: `docs/specs/m72-p2-stage1-scratch.md` (p2s), `docs/specs/m72-mma-verify.md`
(matrix-unit verify); D2 = fork `dev/m72_mq_decode.py` (no spec, no tests); reviews `docs/reviews/m72-p2-stage1/`,
`docs/reviews/m72-mma-verify/`; results `benchmark/results/m72/{P2S.md, MMA.md, SWEEP.md, D1D2.md, e2e/, memory/, realact/}`.

## Goal (verbatim in every brief)

`Qwen3.8-27B-Fable-Distill-OptiQ-4.5bpw-mixed` ships native16 KV + MTP ON. Three dev prototypes show TurboQuant 4 (TQ4) KV can
match or beat it at large context while saving 5.8 / 11.7 GB at 131K / 262K: the fused-dequantize scratch prefill (p2s, measured
end to end 0.973× / 0.982× native16 prefill), the matrix-unit MTP verify kernel (projected 1.10× / 1.19× native16 MTP ON decode),
and the copy-free exact decode kernel D2 (MTP OFF / k = 1). Today none of them is reachable from the server: TQ4 prefill runs the
Python-tiled `quantized_attention` (0.35× at 260K), TQ4 verify runs one singleton decode per drafted token, and every TQ4 decode
call copies the cache's strided state. Build them into the fork as one production attention mode for TQ4 caches, opt-in per pick
from the registry, numerically held to the prototypes' accepted standards, with today's behaviour byte-identical when the mode is
off. Solving it means: the mode exists end to end (registry → mlx-serve → worker → attention), every regime routes as specified
and is tested, the acceptance criteria below hold, and the stack can run an arm with the mode on. No speed bar in 1.3 (1.4
certifies speed, memory and quality).

3. Stack: `bench.provenance` / fingerprint record `tq4_attention` (fingerprint version bump); `m72_e2e_prefill.py` gains a

## Settled constraints

- (operator, C314) One layer's scratch (≈ 1.07 GB at 262,144) may exist at a time; the whole KV cache is never materialized.
  (operator, C316) Scratch fp16. (operator, C312) Verify accuracy = `joint_v1`'s tolerance, not bit-identity; D2 is exact.
  (operator, C313) Large context (≥ 128K) is the target. (C317) Prefill per full-attention layer evaluation; `pipe2` (pipelined
  `async_eval`) was measured and **not kept**: 0.58 % faster at 131,072, below the ≥ 1 % bar (S21-P3, `benchmark/results/m72/e2e/e2e-131072-pipe2.json`).
- (AGENTS.md) `kv_prealloc_tokens = max_kv_cache_size` structurally; `cache_session_shrink` honoured only while idle; thread
  `prefill_step_size`; never assume bf16 speculation lossless; certify MTP ON vs OFF (1.4).
- (designer) Scope of the mode: batch 1, TurboQuant MSE 4-bit keys and values, power-of-two RHT, head dim 256, 24 q / 4 kv
  heads (R = 6) — the shapes the prototypes were measured on. Any other cache or shape falls back to today's path, per call,
  silently (counted, see the self-test record), never an error at request time.
- (designer, verified in code) `maybe_quantize_kv_cache` never converts the **last** cache entry (`generate/common.py`: "Skip
  the last layer"). For the 64-layer hybrid that entry is full-attention layer 63, so 15 of 16 full-attention layers are TQ4
  and layer 63 stays native16. Today `require_environment` refuses `joint_v1` with `kv_bits` set, so layer 63's verify falls to
  the per-query loop. The mode keeps layer 63 native16 (quality-sensitive; unchanged from today's TQ4 behaviour) and gives it
  native16's shipped paths: `fused_v1` prefill (the attention policy, already per-cache) and `joint_v1` verify.

## Regimes and routing (per call; `m72_v1` on, cache in scope)

| regime | condition | path | numerical standard |
|---|---|---|---|
| prefill chunk | L > 1, not speculative verify | p2s: `dequant_rotated` into a capacity-sized fp16 scratch, rotated queries in fp16, MLX fused SDPA `mask="causal"`, inverse rotation | A1 of the p2s spec (rel ≤ 2 × max(production, 2⁻¹²), allclose 3e-2) |
| plain decode | L = 1, T > 2048 | D2 pass 1 + production pass 2, reading the full-cap state in place | bit-identical to today's singleton |
| plain decode | L = 1, T ≤ 2048 | today's single-pass `_fused_mse_decode_kernel` | unchanged |
| verify, k = 1 | one query | as plain decode | bit-identical |
| verify, k ≥ 2 | k ∈ 2…5, lengths consecutive | matrix-unit TQ4 kernel, block cap 512 tokens, production pass 2 | A1 of the mma spec |
| verify, k > 5 or gapped lengths | — | today's per-query loop | unchanged |
| native layer 63 | `KVCache` | `fused_v1` prefill, `joint_v1` verify, SDPA decode | as the shipped native16 pick |
| anything else | batch > 1, other bits / codec / D / R, TQ4 off | today's path | byte-identical |

- Prefill evaluation: after each TQ4 full-attention layer's attention output during a prefill chunk, `mx.eval(out)` (memory spike:
  a lazy 16-layer graph holds ≈ 6.4 scratches). `update_and_fetch` already evaluates K / V for n_new > 1; the added evaluation
  bounds the scratch, not the cache. Placement free (attention module or decoder layer), but exactly once per TQ4 layer per chunk.
- Scratch size = the state's capacity (cap-sized, so MLX's buffer cache reuses one size; T-sized scratch piles stale buffers —
  memory spike). After an idle `cache_session_shrink` the capacity returns to the floor before the next write (existing rule), so
  steady state keeps one size.
- Copy-free: the decode and verify kernels take the cache's full-cap state arrays (`cache.keys`, `cache.values`), never the
  `state` property's strided slice (that slice is what forces today's per-call copy).
- Block plan for verify: the 512-token-per-block policy from `SWEEP.md` (−9–14 % vs the prototype default at k = 3), recorded by
  the self-test; D2 keeps production's block count (`production_num_blocks`) so its result stays bit-identical.

## Residuals carried from the prototype reviews (decided here)

- R1 fp16 query range (mma review #11; also p2s, which casts rotated queries to fp16): the rotations are orthogonal and q passes
  `q_norm` (`nn.RMSNorm`, D = 256), so per element |q′| ≤ ‖q‖₂ ≤ √D · max|γ| (γ = the loaded `q_norm.weight`; ε only shrinks
  it). `tq4_attention.check_fp16_range(model)` computes the bound per full-attention layer at load from the loaded weights and
  refuses the mode (start-up error naming the layer and bound) unless √D · max|γ| ≤ 2¹⁴ (4× under fp16's 65,504, covering
  RoPE / gate round-off). Zero runtime cost; a test plants a γ above the bound and expects the refusal. (Real activations:
  max |q_rot| 8.4.)
- R2 −1e30 empty-block sentinel (mma review #10): kept — it is production pass 1's own sentinel and pass 2's combine
  (`-INFINITY` start) depends on it; scores below −1e30 need inputs outside fp16/bf16 range after R1's bound. Documented in
  `tq4_fast.py`; a test covers fully-masked blocks (no NaN).
- R3 gapped verify lengths (mma review #17): the verifier forms consecutive lengths (`prefix + index + 1`); the dispatch
  asserts consecutiveness and routes anything else to the per-query loop (tested).
- R4 D2 has no tests and asserts T > 2048: 1.3 adds them (bit-identity to the singleton at T ∈ {2049, 4097, 8193, 40000},
  k = 1, both block regimes) and the routing above covers T ≤ 2048.

## Interfaces

```python
# mlx_vlm/tq4_fast.py  (kernels; batch 1; shapes asserted)
def dequant_rotated(cache, T, *, dtype=mx.float16) -> tuple[mx.array, mx.array]          # as dev/m72_scratch_prefill
def prefill_attention(cache, queries, scale) -> mx.array                                 # p2s; T = cache.offset
def decode_attention(cache, queries, scale) -> mx.array                                  # D2 (T > 2048) / single-pass
def verify_attention(cache, queries, scale, lengths) -> mx.array                         # k = 1 → decode, 2…5 → mma
def native16_verify_attention(keys, values, queries, scale, lengths) -> mx.array         # not used by m72_v1 (layer 63
                                                                                         # uses joint_v1); kept for 1.4 A/B
def supports(cache, queries) -> bool                                                     # the scope test, no side effects
def self_test() -> dict                                                                  # small synthetic caches vs references

# mlx_vlm/tq4_attention.py  (the mode; mirrors mtp_verify_scan)
MODES = ("m72_v1",)
def resolve_mode(value: str | None) -> str | None
def require_environment(mode, *, kv_bits, kv_quant_scheme, batch_max) -> None           # refuses kv_bits != 4, scheme != turboquant
def check_fp16_range(model) -> dict                                                      # R1; raises on violation
def apply_to_model(model, mode) -> int                                                   # stamps attention modules; returns count
def self_test_model(model, mode) -> dict                                                 # tq4_fast.self_test + fragment mapping
```

- `m72_v1` off (absent): no module stamped, no import of `tq4_fast` at request time; every path byte-identical to today (A3).
- Load-time order (server): resolve → require_environment → check_fp16_range → apply_to_model → self_test_model; any failure
  refuses to start (exit nonzero, message), never a silent fallback. Per-call fallbacks (out-of-scope caches) are counted in a
  per-process counter exposed in the worker's `/health` details (name free), so a run can prove the mode ran.
- `mtp_verify_scan: joint_v1` + `kv_bits: 4` is accepted only with `tq4_attention: m72_v1`; `JointV1Policy.classify` keeps
  sending TQ caches to `per_query` (the mode's hook runs first for them), native caches to `joint`.

## Acceptance criteria (pre-registered)

- A1 Kernel accuracy (fork GPU tests, on `tq4_fast`, not `dev/`): p2s and mma meet their prototype specs' A1 on the prototypes'
  sweeps and checkpoints ≤ 40,960 tokens (cap 40,960), with each spec's negative controls failing; D2 and the k = 1 verify are
  bit-identical to today's singleton (R4 rows); no NaN / Inf, including fully masked blocks (R2).
- A2 Routing: one test per row of the routing table asserts the path taken (spy on the kernels) and the output standard; the
  layer-63 native cache takes `joint_v1` for verify with `kv_bits: 4` + `m72_v1`; gapped lengths and k = 6 take the per-query loop.
- A3 Off is today: with the mode absent, a fixed-seed greedy generation (synthetic small Qwen3.5-family model in tests; the
  real `Qwen3.8-27B-Fable-Distill-OptiQ-4.5bpw-mixed` in the stack smoke) produces byte-identical tokens and logits to the
  parent commit, TQ4 and native16 both.
- A4 On is consistent: with `m72_v1`, MTP OFF greedy decode on TQ4 is token-identical to today's TQ4 MTP OFF after an identical
  prefill state (D2 exact); prefill logits of the last prompt token within A1's tolerance of today's TQ4 prefill (real model,
  8K and 32K prompts, stack smoke).
- A5 Memory (stack, real model, 131,072-token prefill, fresh process, OS footprint ledger + MLX allocator): the production path's
  peak delta ≤ the dev harness's `tq4_p2s:layer` peak delta (4.30 GB OS ledger, `benchmark/results/m72/e2e/`) + layer 63's
  native16-minus-TQ4 cache bytes at 131,072 (≈ 0.40 GB, computed from the shapes; S21-P2) + 0.25 scratch.
- A6 Speed sanity (stack, real model, one order-balanced pair at 131,072, not a certification): production prefill ≥ 0.97× the
  dev harness's `tq4_p2s:layer` (same box state); a short MTP ON decode run at 32K completes with the fallback counter = 0 for
  in-scope calls.
- A7 Range check (R1): refuses a planted γ above the bound; passes on the real model (bound recorded).
- A8 Config flow: mlx-serve tests for the key / validation / pass-through; worker env + fingerprint record the mode; stack
  provenance tests; fork, mlx-serve and stack clean-clone gates pass.

## Non-goals

Registry pick change or certification (1.4), native16 matrix-unit verify in shipping config (C313 (1) unmet), batch > 1, other
codecs / bit widths / shapes, stage 2–3 prefill (own attention core, in-kernel unpack), MLX rebuild, an 8-bit or mixed-width TQ path for
the last layer.

## Assumptions (designer)

- The prototypes' measured accuracy transfers to the promoted kernels unchanged (same code; the tests re-establish A1).
- MLX's fused SDPA output depends only on its inputs; the buffer cache recycles the per-layer scratch (memory spike verified).
- Qwen3.8-27B layers: full attention every 4th layer (`full_attention_interval = 4`), last index 63 (`language.py`).

## Open questions (for the design review; designer's recommendation first)

1. One registry value for all three kernels vs a value per regime. Rec: one (`m72_v1`): they are certified together as the
   pick's shipped state (C204); per-regime env switches exist only in tests. Counterpoint: 1.4 cannot ablate one kernel in a
   served arm without a dev override.
2. Layer 63: keep native16 (as today) vs convert it to TQ4. Rec: keep (quality-sensitive by upstream's own comment; ≈ 0.8 GB of
   the saving at 262K stays on the table). Counterpoint: a mixed cache keeps two verify paths in the hot loop.
3. Verify block cap 512 fixed vs the prototype's plan. Rec: 512 (measured). Counterpoint: measured at k = 3 only.
