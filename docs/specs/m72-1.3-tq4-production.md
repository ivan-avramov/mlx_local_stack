## Goal (verbatim in every brief)

`Qwen3.8-27B-Fable-Distill-OptiQ-4.5bpw-mixed` ships native16 KV + MTP ON. Three dev prototypes show TurboQuant 4 (TQ4) KV can
match or beat it at large context while saving memory: the fused-dequantize scratch prefill (p2s, measured end to end 0.973× /
0.982× native16 prefill), the matrix-unit MTP verify kernel (projected 1.10× / 1.19× native16 MTP ON decode), and the copy-free
exact decode kernel D2 (MTP OFF / k = 1). Today none of them is reachable from the server: TQ4 prefill runs the Python-tiled
`quantized_attention` (0.35× at 260K), TQ4 verify runs one singleton decode per drafted token, and every TQ4 decode call copies
the cache's strided state. Build them into the fork as one production attention mode for TQ4 caches, opt-in per pick from the
registry, numerically held to the prototypes' accepted standards, with today's behaviour byte-identical when the mode is off.
Solving it means: the mode exists end to end (registry → mlx-serve → worker → attention) on the server path that runs MTP, every
regime routes as specified and is tested, the acceptance criteria below hold, and the stack can run an arm with the mode on. No
speed bar in 1.3 (1.4 certifies speed, memory and quality).

## Settled constraints

- (operator, C314) One layer's scratch (≈ 1.07 GB at 262,144) may exist at a time; the whole KV cache is never materialized.
  (operator, C316) Scratch fp16. (operator, C312) Verify accuracy = `joint_v1`'s tolerance, not bit-identity; D2 is exact.
  (operator, C313) Large context (≥ 128K) is the target. (C317) Prefill evaluated per full-attention layer; `pipe2` (pipelined
  `async_eval`) was measured and **not kept**: 0.58 % faster at 131,072, below the ≥ 1 % bar (S21-P3,
  `benchmark/results/m72/e2e/e2e-131072-pipe2.json`).
- (AGENTS.md) `kv_prealloc_tokens = max_kv_cache_size` structurally (262,144 for this pick); `cache_session_shrink` honoured
  only while idle; thread `prefill_step_size`; never assume bf16 speculation lossless; certify MTP ON vs OFF (1.4).
- (designer, verified in code) **Served path.** MTP runs only on the server's inline cached-session path (chat-id'd requests,
  `_process_cached_request` → `generate_step`, B = 1, caches from `maybe_quantize_kv_cache`: `TurboQuantKVCache` / `KVCache`).
  Requests without a chat id go through continuous batching, which disables MTP (`_speculation_fallback_reason` →
  `mtp_batched`) and builds `BatchTurboQuantKVCache` / `BatchKVCache` even at batch 1. The mode serves the inline path;
  batch-cache classes route to today's path and are counted (reason `batch_cache`). The benchmark and daily-driver traffic this
  pick is certified on is chat-id'd.
- (designer, verified in code) **Layer 63.** `maybe_quantize_kv_cache` never converts the last cache entry
  (`generate/common.py`: "Skip the last layer"); for the 64-layer hybrid that is full-attention layer 63, so 15 of 16
  full-attention layers are TQ4 and layer 63 stays native16 (as today's TQ4). The mode gives it native16's shipped paths:
  `fused_v1` prefill and `joint_v1` verify — hence the mlx-serve and `require_environment` changes above. The policy stamps stay
  on all 16 modules; the TQ branch in `base.py` precedes the policy check, so the stamp is inert on TQ4 layers — never remove it.
- (designer) **Scope predicate** `tq4_fast.supports(cache, queries, mask, sinks)` — True iff all hold, else today's path with a
  counted reason: `type(cache) is TurboQuantKVCache` (not the batch class); both codecs `_TurboQuantMSECodec`, key and value bits 4,
  power-of-two RHT rotation; `queries.shape[0] == 1`, n_q = 24, n_kv = 4, D = 256, `queries.dtype` bf16; `mask in (None,
  "causal")`; `sinks is None`; the cache's `_decode_2pass_use_legacy` false and no per-cache block override
  (`_decode_2pass_num_blocks` unset). Per call, never an error at request time.

## Modes (C319)

- `m72_v1` — the fast mode: MTP verify blocks through the matrix-unit kernel (joint-tolerance, **not exact**: TQ4 MTP ON can emit
  different tokens than MTP OFF for the same seed; 1.4 certifies it as a lossy lever, S21-P9).
- `m72_exact` — the lossless mode: identical to `m72_v1` except that verify blocks with k ≥ 2 go through D2's exact multi-query
  kernel (each query bit-identical to the singleton at its own T_eff), so TQ4 MTP ON emits exactly what TQ4 MTP OFF emits (the
  native16 `joint_v1` property, M58 gate 1). Prefill is mode-independent (it is the same with MTP ON and OFF).

## Regimes and routing (per call; a mode on and `supports(...)` true)

T_eff = the key length the caller passes (`kv_sequence_length(keys_state)`), never `cache.offset`: the per-query fallback slices
the state below the offset (`speculative_verifier.py`), so a kernel reading `cache.offset` would attend to later draft tokens.

| regime | condition | path | numerical standard | counter |
|---|---|---|---|---|
| prefill chunk | L > 1, not speculative verify, not the short-chunk row | p2s: `dequant_rotated` (T = T_eff) into a capacity-sized fp16 scratch, rotated queries fp16, MLX fused SDPA `mask="causal"` (queries aligned to the last L keys), inverse rotation in fp32 | p2s spec A1 | `p2s` |
| short prefill chunk | 2 ≤ L ≤ 5, T_eff > 2048, not speculative verify (C318 / S2) | the verify kernel with lengths T_eff − L + 1 … T_eff (same causal semantics, no scratch) | mma spec A1 | `mma_prefill` |
| plain decode | L = 1, T_eff > 2048 | D2 pass 1 + production pass 2 on the full-cap state in place, T_eff tokens | bit-identical to today's singleton on the same state | `d2` |
| plain decode | L = 1, T_eff ≤ 2048 | today's single-pass `_fused_mse_decode_kernel` | unchanged | `single_pass` |
| width-1 verify | `_mtp_commit_pending_token` (the only width-1 verify; normal rounds have k ≥ 2) | as plain decode, through `base.py` | bit-identical | `d2` / `single_pass` |
| verify, k ≥ 2 (`m72_v1`) | k ∈ 2…5, lengths consecutive (`prefix + i + 1`) | matrix-unit TQ4 kernel, 512 tokens per block, production pass 2 | mma spec A1 | `mma` |
| verify, k ≥ 2 (`m72_exact`) | k ∈ 2…5, lengths consecutive, lengths[0] > 2048 | D2 multi-query pass 1 (each query's block count = the singleton's for its own T_eff, including tier straddles) + production pass 2 | each query bit-identical to the singleton | `d2_verify` |
| verify, k ≥ 2 (`m72_exact`), short | lengths[0] ≤ 2048 | today's per-query loop (exact) | unchanged | `per_query:short` |
| verify, other | k > 5 or gapped lengths | today's per-query loop (each query through `base.py` → `d2` / `single_pass` with its own T_eff) | unchanged per query | `per_query:{k_gt_5, gapped}` |
| native layer 63 | `KVCache` | `fused_v1` prefill, `joint_v1` verify, SDPA decode | as the shipped native16 pick | `native:{prefill, verify, decode}` |
| out of scope | `supports` false, or mode absent | today's path | byte-identical | `fallback:<reason>` (mode on only) |

- Prefill evaluation: `mx.eval(out)` after each TQ4 full-attention layer's attention output in a prefill chunk, exactly once per
  layer per chunk (memory spike: a lazy 16-layer graph holds ≈ 6.4 scratches); placement free (attention module or decoder layer).
- Scratch size = the state's capacity (one size, so MLX's buffer cache reuses it; T-sized scratch piles stale buffers — memory
  spike). After an idle `cache_session_shrink` the capacity returns to the floor before the next write (existing rule).
- Copy-free: decode and verify kernels take the cache's full-cap state arrays (`cache.keys`, `cache.values`) plus T_eff, never the
  `state` property's strided slice (the slice is what forces today's per-call copy).
- Verify block plan: 512 tokens per block (`SWEEP.md`: at k = 3 −8 % at 131,072, −15 % at 260,096 vs the prototype default; k = 1
  and 5 were swept too). Block-plan changes alter summation order (≤ 5.4e-3 vs the default plan in `SWEEP.md`), so A1 is
  re-established on the 512 plan.
- D2 bit-identity contract: D2 replicates the singleton's per-(query, head, block) arithmetic order and uses the block count the
  singleton would use for T_eff on the non-legacy path (`production_num_blocks`, including the > 65,536 tier); the legacy path and
  block overrides are outside `supports`, and `require_environment` refuses the mode when `TQ_DECODE_2PASS_LEGACY` is set.
- Route counters: per-process, by counter name above, exposed in the worker's `/health` details and in `bench.provenance`'s
  manifest (name of the field free); reset never during a process.

## Residuals carried from the prototype reviews (decided here)

- R1 fp16 range. Query side (mma review #11; p2s casts rotated queries to fp16): the rotations are orthogonal and q passes
  `q_norm` (`nn.RMSNorm`, D = 256), so per element |q′| ≤ ‖q‖₂ ≤ √D · max|γ| (γ = the loaded `q_norm.weight`; ε only shrinks it;
  mma additionally scales by `scale` first). K / V side: scratch values are `codebook[idx] · norm`, with the norm stored fp16 and
  the MSE codebook's centroids in [−1, 1], so |K_rot|, |V_rot| ≤ the stored fp16 norm (no new overflow). `check_fp16_range(model,
  caches)` computes per full-attention layer √D · max|γ| and max|codebook| at load and refuses the mode (start-up error naming the
  layer and value) unless √D · max|γ| ≤ 2¹⁴ and max|codebook| ≤ 1. Zero runtime cost; tests plant violations of each.
- R2 −1e30 empty-block sentinel (mma review #10): kept — production pass 1's own sentinel; pass 2's combine (`-INFINITY` start)
  depends on it; scores below −1e30 need inputs outside R1's bounds. Documented in `tq4_fast.py`; a test covers fully-masked
  blocks (no NaN).
- R3 gapped verify lengths (mma review #17): the dispatch checks consecutiveness and routes anything else to the per-query loop.
- R4 D2 had no tests and asserts T > 2048: 1.3 adds them (A1 rows) and routing covers T ≤ 2048.

## Interfaces

```python
# mlx_vlm/tq4_fast.py  (kernels; batch 1; preconditions asserted)
def supports(cache, queries, mask=None, sinks=None) -> tuple[bool, str | None]   # (in scope, fallback reason)
def dequant_rotated(cache, T, *, dtype=mx.float16) -> tuple[mx.array, mx.array]  # as dev/m72_scratch_prefill, capacity-sized
def prefill_attention(cache, queries, scale, T) -> mx.array                       # p2s; queries at positions [T - L, T)
def decode_attention(cache, queries, scale, T) -> mx.array                        # D2 (T > 2048) / single-pass
def verify_attention(cache, queries, scale, lengths, *, exact=False) -> mx.array   # k = 2…5, consecutive; exact → D2
def route_counts() -> dict[str, int]
def self_test() -> dict                                                           # small synthetic caches vs references

# mlx_vlm/tq4_attention.py  (the mode; mirrors mtp_verify_scan)
MODES = ("m72_v1", "m72_exact")
def resolve_mode(value: str | None) -> str | None
def require_environment(mode, *, kv_bits, kv_quant_scheme, attention_policy, mtp_verify_scan) -> None
    # refuses unless kv_bits == 4, scheme turboquant, attention_policy fused_v1, mtp_verify_scan joint_v1,
    # TQ_DECODE_2PASS_LEGACY unset
def check_fp16_range(model, caches=None) -> dict                                  # R1; raises on violation
def apply_to_model(model, mode) -> int                                            # stamps attention modules; returns count
def self_test_model(model, mode) -> dict                                          # tq4_fast.self_test + fragment mapping
```

- Mode absent: no module stamped, `tq4_fast` not imported at request time, counters not incremented; every path byte-identical
  to today; `mtp_verify_scan.require_environment` keeps refusing `kv_bits` (A3).
- Server load order (`server/generation.py`): resolve the TQ4 mode → `tq4_attention.require_environment` → attention policy
  (`_apply_attention_policy_from_env`) → MTP verify (`_apply_mtp_verify_from_env`, whose `require_environment` accepts
  `kv_bits` = 4 iff the TQ4 mode resolved to `m72_v1`) → `check_fp16_range` → `apply_to_model` → `self_test_model`. Any failure
  refuses to start (exit nonzero, message); never a silent fallback at load.
- `JointV1Policy.classify` keeps sending TQ caches to `per_query` (the mode's hook runs first for them) and native caches to
  `joint` (layer 63).

## Acceptance criteria (pre-registered)

- A1 Kernel accuracy (fork GPU tests on `tq4_fast`, not `dev/`), caches preallocated to 262,144: p2s and mma meet their
  prototype specs' A1 (rel ≤ 2 × max(production rel error, 2⁻¹²) and allclose 3e-2 vs the fp32 reference) on the prototypes'
  sweeps (≤ 40,960) **and** at T ∈ {65,537, 131,072, 260,096} (heads 0 / 6 / 12 / 18; k = 2, 3, 5 for mma; L = 512 and L = 37
  for p2s), with each spec's negative controls failing; D2 bit-identical to today's singleton (same state, same T_eff) at
  T ∈ {2,049, 4,097, 8,193, 40,000, 65,537, 131,072, 260,096} and on a state sliced below the offset (the per-query fallback
  shape); D2 multi-query (`m72_exact` verify) per query bit-identical to the singleton for k = 2…5 at the same T values and at
  lengths straddling the 65,536 tier (e.g. 65,535 … 65,538); no NaN / Inf, including fully masked blocks (R2).
- A2 Routing: one test per routing row asserts the path (spy on the kernels), the counter and the output standard, including:
  k = 6 and gapped lengths take the per-query loop with each query bit-identical to a singleton at its own T_eff above 2048;
  the width-1 commit-pending verify; under `m72_exact`, k = 2…5 verify takes `d2_verify` and lengths[0] ≤ 2048 takes
  `per_query:short`; batch-cache classes, array masks, sinks, the legacy flag and block overrides fall back with
  their reasons; a 3-token non-verify prefill chunk at T_eff > 2048 takes `mma_prefill`; layer 63 takes `fused_v1` prefill (`force_fused`) and `joint_v1` verify with `kv_bits: 4` + `m72_v1`.
- A3 Off is today: with the mode absent, fixed-seed greedy generation (a synthetic small Qwen3.5-family model in fork tests) is
  byte-identical in tokens and logits to the parent commit, TQ4 and native16; `require_environment` refusals unchanged.
- A4 On is consistent (same process): (a) build a TQ4 cache by a mode-off prefill, snapshot it, decode n = 64 greedy tokens MTP
  OFF with the mode off, restore the snapshot, apply the mode, decode again → token- and logit-identical (D2 exact; synthetic model
  in the fork, the real model in the stack smoke at 8K and 32K prompts); (c) `m72_exact`: from the same snapshot, MTP ON greedy and
  seeded-sampling decode emit exactly the MTP OFF tokens (n = 256; synthetic model in the fork, real model in the stack smoke); (b) last-prompt-token logits after a mode-on prefill vs a
  mode-off prefill of the same prompt within A1's tolerance (real model, 8K and 32K).
- A5 Memory (stack, real model, fresh process per leg, OS footprint ledger + MLX allocator, prompt 131,072 tokens, **capacity
  262,144 in both legs**): leg X = dev `tq4_p2s:layer` with `--capacity 262144`; leg P = `tq4_m72`. P's peak delta ≤ X's peak
  delta + (layer 63 native16 − TQ4 cache bytes at capacity 262,144, computed from the shapes and recorded) + 0.25 scratch.
- A6 Served-path smoke (stack, real model, the server started from a committed arm `main_models.yaml` with `kv_bits: 4` +
  `tq4_attention: m72_v1`, chat-id'd requests): one 32K-prompt MTP ON request completes; counters show `p2s` > 0, `mma` > 0,
  `d2` > 0 (commit-pending / any width-1) or recorded as 0 with the reason, `native:*` > 0, `fallback:*` = 0, and `per_query:*`
  recorded (not gated); for `m72_exact` the same with `d2_verify` > 0 and `mma` = 0. Divergence diagnostic (S21-P9, not gated):
  10 seeded-random prompts from the stack's coding corpus, 8K–32K tokens, deployed sampling, 1,024 generated tokens each, run
  under `m72_v1` and `m72_exact` with the same seed; report per prompt the first differing token position, or none (the streams are
  not compared past the first difference, which changes everything after it); speed sanity: production prefill at 131,072 ≥ 0.97× leg X of A5 (same box state; not a certification).
- A7 Range check (R1): refuses planted violations of each bound; passes on the real model (values recorded).
- A8 Config flow: mlx-serve tests (key, the four-way validation, refusals of `fused_v1` / `joint_v1` with `kv_bits: 4` without
  the mode, pass-through); worker env, manifest and fingerprint record the mode and counters; stack provenance tests; fork,
  mlx-serve and stack clean-clone gates pass.

## Non-goals

Registry pick change or certification (1.4), native16 matrix-unit verify in shipping config (C313 (1) unmet), speculation on the
continuous-batching path, batch > 1, other codecs / bit widths / shapes, stage 2–3 prefill (own attention core, in-kernel unpack),
MLX rebuild, an 8-bit or mixed-width TQ path for the last layer.

## Assumptions (designer)

- The prototypes' measured accuracy transfers to the promoted kernels unchanged (same code; A1 re-establishes it, now at target
  context).
- MLX's fused SDPA output depends only on its inputs; the buffer cache recycles the per-layer scratch (memory spike verified).
- Qwen3.8-27B layers: full attention every 4th layer (`full_attention_interval = 4`), last index 63 (`language.py`).
