# M76 B1 — `bench.p475_kv` campaign `f45` (`Qwen3.8-27B-Fable-Distill-OptiQ-4.5bpw-mixed`, TQ4 + `tq4_attention` arms) — SPEC v1, 2026-11-11 (four-eyes light; C325)

## Goal

`bench.p475_kv` (`docs/specs/p475-stage1-contract.md`) measures a KV-format matrix through the shipped stack, but only for
`Qwen3.8-27B-mlx-uniform-4bit`: the pick, its short label `u4`, its six arms, TQ4 as the base arm, the leg / branch names, the
scratch / state / harvest / matrix paths and the per-arm registry edits are module constants, and its edit model can only rewrite
lines that already exist. M76 stage 1 (`docs/specs/m76-tq4-certification.md` §7) needs the same instrument for
`Qwen3.8-27B-Fable-Distill-OptiQ-4.5bpw-mixed` with arms N16 (the shipped entry, base), X (`kv_bits: 4` + `tq4_attention:
m72_exact`), V (`kv_bits: 4` + `tq4_attention: m72_v1`) and XO (X with MTP OFF), with the mode proven engaged on every TQ4 leg and
S18-P13's absolute floor in the instability rule. Solving it means: `bench.p475_kv --campaign f45 …` prepares, preflights, runs
and tabulates exactly those arms with every existing P475 rule (R1–R22, the stage-1 contract) applied, under its own paths, while
`--campaign u4` (the default) is byte-identical to today in argv, paths, receipts, dossiers and the regenerated
`MATRIX.Qwen3.8-27B-mlx-uniform-4bit.md`.

## Scope (files)

`benchmark/bench/p475_kv.py`, `benchmark/bench/kv_line.py`, `benchmark/bench/capacity_ladder.py` only if a rung rule needs the
campaign; tests `benchmark/bench/tests/test_m76_b1_*.py`. Read-only: every other file (`chain_ops.py`, `run_capacity.py`,
`provenance.py`, `p426_*`, the forks).

## Settled constraints

- (C322 / C323 / C325) Stage 1 arms, order and grid as M76 §7; M70's floor (0.02) for this campaign (S22-P2).
- (P475 contract) R1–R22 and the leg lifecycle unchanged in substance for every campaign.
- (AGENTS.md) Arms are stack commits in worktrees; full registry names; nothing written outside `$STACK_WORKDIR` / the results dir.

## Interfaces

**Campaign table.** A frozen dataclass `Campaign` holding today's module constants as fields, and `CAMPAIGNS = {"u4": …, "f45": …}`.
Every function that reads a constant reads the active campaign (passed through `Config`, never a mutable global). `--campaign`
(default `u4`) on every subcommand; a dossier, receipt or state file from another campaign refuses (recorded `campaign` field;
a `u4` record without the field reads as `u4`).

**Arm edits for `f45`** (applied to the base entry; the arm diff must be exactly these lines + the comment, R1):
- N16: none (the base commit itself, like `u4`'s TQ4).
- X: `kv_bits: 0 …` → `kv_bits: 4` (the trailing comment may be replaced by the arm comment); ADD `tq4_attention: m72_exact` on the
  line after `kv_bits`.
- V: as X with `m72_v1`.
- XO: as X, plus `draft_kind`, `draft_model` and `mtp_verify_scan` lines commented out (`# ` prefix, value kept).
The edit model gains "add a line after key K" and "comment a line"; adding a key that already exists, or editing a key the entry
lacks, refuses.

**Expected KV line (`kv_line`)** for `f45`: N16 as today's native rule; X / V / XO as today's TQ4 rule (bits 4, `turboquant`,
split fields None, group 64, start 0, `TQ_KV_QUANT_MODE` `'mse'`).

**Mode proof (new, every `f45` leg; R5-style: a failure after load → INVALID before the driver; after the driver → INVALID).**
Source: the driver's manifest (`run_capacity` already stores `manifest["tq4_route_counts_at_creation"]` and
`manifest["router_exit"]["tq4_route_counts_at_exit"]`, `bench.provenance.tq4_route_counts`) and the worker's self-test stderr line
`tq4_attention=<mode> self-test: …` in the worker log (secondary record). Rules:
- N16: mode `off`, no counters, no self-test line.
- X: mode `m72_exact`; exit − creation deltas: `p2s` > 0, `d2_verify` > 0, `native:prefill` > 0, `native:verify` > 0, `mma` == 0,
  every `fallback:*` == 0.
- V: mode `m72_v1`; `p2s` > 0, `mma` > 0, `native:prefill` > 0, `native:verify` > 0, `d2_verify` == 0, `fallback:*` == 0.
- XO: mode `m72_exact`; `p2s` > 0, `d2` > 0, `native:prefill` > 0, `native:decode` > 0, `mma` == 0, `d2_verify` == 0,
  `native:verify` == 0, `fallback:*` == 0.
Counters absent where required, or a mode mismatch → INVALID with the reason. The deltas are recorded in the receipt and dossier.

**Instability floor (`f45`):** a cell flags `spread` only when `|mean − 1| > floor` and `|r1 − r2| > |mean − 1| / 2`, or when
`|r1 − r2| > floor`; `reversal` needs `|r1 − 1| > floor` and `|r2 − 1| > floor` besides the sign change. `u4` keeps today's rule.

**Matrix (`f45`):** `benchmark/results/m76/matrix/MATRIX.Qwen3.8-27B-Fable-Distill-OptiQ-4.5bpw-mixed.md` (or `.PARTIAL.md`), today's
tables plus: ratios V / X per rung and block (decode, prefill, peak); the route-counter deltas per leg; a "stage-4 trigger" line:
**met** iff V / X decode ≥ 1.05 at 131,072 and at 260,096 in both blocks and no unresolved instability flag on those cells, else
**not met** with the failing cells named.

**Preflight:** as today (`qualify --kv-arm`, OFF for every arm, `--engagement` for ON arms); the arm name passed to `qualify` is
the campaign's; whether `qualify` accepts the mode is B2's concern (a refusal is a preflight refusal, as today).

## Acceptance criteria

1. Red-first tests (mocked ops, real argv / env / receipt / log / manifest formats): the `f45` campaign table; arm registry text
   for X / V / XO from the real committed `main_models.yaml` entry (diff = exactly the listed lines + comment; adding an existing
   key / editing a missing key refuses); leg / branch names and the leg regex; the ABBA order; the mode proof per arm (each
   counter rule, a mode mismatch, counters missing, a fallback > 0 → INVALID); the floor (the two S18-P13 cells — AF4 8192 prefill
   spread 0.009 with mean ≈ 1.00 — flag under `u4`, do not under the floor); the V / X ratios and the trigger line; campaign
   isolation (paths; a `u4` dossier under `f45` refuses and vice versa).
2. `u4` byte-identity: a golden test, written and green before the change, regenerates `MATRIX.Qwen3.8-27B-mlx-uniform-4bit.md` from
   the committed `benchmark/results/p475/` dossiers byte-identically, and pins the `u4` argv / paths / receipt keys of a mocked leg.
3. The existing `p475`, `run_capacity`, `capacity_*`, `kv_line`, `bench_watch`, `chain_ops` and `p426_*` tests pass unchanged; the
   stack suite passes or fails only as on the baseline.
