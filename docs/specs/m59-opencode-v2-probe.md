## P149 — hermetic invocation (VERIFIED recipe, FACTS "Hermetic recipe for 2.x")

Per run `<R> = $STACK_WORKDIR/opencode-probe-v2/run-<run_id>/`; per item `<S> = $STACK_WORKDIR/scratch/<tmp>/<exercise>` (git-initialised,
no AGENTS.md, NOT under `<R>/home`).

Environment, built from an EMPTY base (not the parent env minus `OPENCODE_*`; v2 reads PATH/HOME/XDG only):

```
PATH=/opt/homebrew/bin:/usr/bin:/bin  HOME=<R>/home  XDG_CONFIG_HOME=<R>/cfg  XDG_DATA_HOME=<R>/data  XDG_STATE_HOME=<R>/state
XDG_CACHE_HOME=<R>/cache  TMPDIR=<R>/tmp/  OPENCODE_CONFIG_DIR=<R>/cfg/opencode  OPENCODE_DISABLE_PROJECT_CONFIG=1
OPENCODE_DISABLE_MODELS_FETCH=1  OPENCODE_DISABLE_AUTOUPDATE=1  OPENCODE_DISABLE_FILEWATCHER=1
OPENCODE_CONFIG_CONTENT=<per-item seed overlay, P150>  PWD=<S>  TERM=dumb  NO_COLOR=1
```

Command (cwd=`<S>`, stdin DEVNULL, stdout → `<S>/.opencode_probe_events.jsonl`, stderr → `<S>/.opencode_probe_stderr.txt`):

```
opencode run --standalone --model mlx-local/<model> --format json --title probe "<prompt>"
```

Transcript afterwards, same env + cwd: `opencode session export <ses_id> --standalone` (VERIFIED 7a). The session id comes from the
`step_start`/`step_finish` events' `sessionID` (first event); no `session list` call.

Changes vs 1.18 and why: `--standalone` (VERIFIED: without it the run joins the operator's background service and inherits ITS env);
`--title probe` (VERIFIED 3: suppresses the title request; belt-and-braces with `agents.title.disabled`); `PWD` explicit (VERIFIED 8:
cwd alone is ignored when a parent PWD exists; a decoy PWD re-rooted the session and denied the scratch read); `XDG_CACHE_HOME`
per run, NOT the shared cache (v2 downloads ripgrep into `<cache>/bin` lazily; the 1.18 "shared cache + inventory hash" rule is
replaced by a per-run cache seeded with the box's `rg` on PATH — `cache_bin_inventory_sha256` stays in the identity, computed on
the run's cache after the first item). The binary is `/opt/homebrew/bin/opencode` resolved to its Cellar path and sha-recorded;
`OPENCODE_PROBE_BIN` overrides as today; `opencode --version` runs under the bench env (rule: not read-only).

## P151 — M50 policy change for v2 (C131: accepted in principle; the exact rule)

`provenance.opencode_router_base` today refuses any of `OPENCODE_CONFIG_CONTENT`, `OPENCODE_CONFIG`, `OPENCODE_CONFIG_DIR`. New
function `provenance.opencode_v2_destination(run_dir, env, model, expected_overlay, opencode_bin)`; the 1.18 function is unchanged.

Tripwire rule (fail-closed, every clause a refusal with the M50 text):
1. `OPENCODE_CONFIG` must be ABSENT. `OPENCODE_CONFIG_DIR` must equal `<R>/cfg/opencode` (realpath) AND that directory must contain
   exactly `opencode.json` (sha == `benchmark/opencode_bench_v2.json`) and `plugins/noretry.js` (sha == the repo file) and nothing
   else. `OPENCODE_CONFIG_CONTENT` must parse to a dict EQUAL to the expected per-item overlay (one provider, one model, one key
   `body.seed` with the expected int) — any extra key refuses. `OPENCODE_DISABLE_PROJECT_CONFIG` must be `"1"`. `HOME` and every
   `XDG_*` must be under `<R>`.
2. Destination from opencode itself: `opencode api GET /api/config --standalone` with the item's env/cwd/PWD (VERIFIED 9: returns the
   raw document list — base file with `path` + `info.providers`, the config dir, the CONTENT document with `path: null`). Rule:
   the list has exactly the documents the recipe predicts (one with `path` == `<R>/cfg/opencode/opencode.json`, one `path: null`
   equal to the overlay; a project document is a refusal since project config is disabled); EVERY document that declares
   `providers.mlx-local.settings.baseURL` declares the carrier's; at least one does; no document declares another `providers.mlx-local.
   settings` key; the `plugins` list of the file document equals the carrier's. There is no merged view, so "every source agrees"
   is the destination proof. The base URL then goes through `assert_served_config` (owner pid == entry pid) exactly as today.
3. `assert_served_config_unchanged` at exit as today; drift stamps `served_config_drift`.
4. End-to-end proof is NOT per item (it would read the worker log): the session-pinning gate's A4 leg (P157) shows the worker log
   `session=<ses_ id>` for a v2 run on every request, once per router start; its result is recorded in the manifest
   (`a4_v2_pass`, gate run id) and the probe refuses to start a chain (n ≥ 40 total) without a PASS recorded against the same
   router pid. `--limit 5` smokes may run before A4.
5. Everything else M50 already requires (sole owner of :8000 is mlx-serve with the driver's registry, local host only, no proxy)
   is unchanged. AGENTS.md M50 bullet gains one sentence naming the v2 exception; `benchmark/README.md` gains the rule table.

## P162 — where I recommend against the obvious alternative

- **Not** keeping 1.18 alive alongside v2 "for pooling": the box, the operator and every future row are on v2; 1.18 rows stay as
  history (C103 scaffold rule), and a live 1.18 path is a second thing to keep hermetic.
- **Not** reading the worker log per item for the session proof: the probe would then depend on log format and a second file
  handle; A4 once per router start plus `requests_observed` and the session id on the row is the same evidence at a tenth of the
  coupling.
- **Not** `compaction.auto: true` in the bench: an overflow would silently summarise the prompt with the model under test and the
  row would look clean; OFF makes it an outcome (`context_overflow`), which is what a benchmark wants.
- **Not** a lean `-opencode.skill` variant for the chain: the built-in `opencode`/`report` skills are part of the v2 scaffold the daily
  driver has; removing them would measure a scaffold nobody uses. Recorded as a candidate OFAT axis.
- **Not** relying on the dynamic `max_completion_tokens`: it is ignored by the fork anyway; `max_tokens` in `body` is the only cap
  the server honours (VERIFIED 4c), so the carrier must send it.
- **Risk kept open:** the `retry` hook is experimental; `provider` API endpoints are empty on a fresh standalone server (VERIFIED 9,
  cause unproven) — the destination check therefore uses `/api/config` documents only; if a future version empties that too, the
  tripwire refuses (no fallback to "default 8000").
