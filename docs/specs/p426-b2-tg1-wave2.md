## 2. Router ownership (P457)

The CHAIN owns router start, load, A4 gate, M50, worker tripwires, unload and stop (its reviewed lifecycle). The P426 tg1 leg
(`p426_leg.run_chain_leg`) does NOT start a router:

- **Pre (refuse → NOT_STARTED):** the Wave-1 `_guard_pre` unchanged (receipt absent, frozen pins, destinations absent,
  registry delta / OFF verbatim, target + drafter snapshot pins, power + orphan gate, nothing busy) + the G4 marker (§8) +
  the chain out-root absent.
- **Run:** the chain argv (§4) with `MLX_SERVE_CONFIG` = the arm registry, timeout §9.
- **Exit (any problem → INVALID):** chain rc 0; `chain.json` status `finished`, every load `done`, `restarts` / archives /
  quarantine empty, `check_realized` passed; the worker cmdline the chain recorded passes `model_argv_problems` (ON: the
  three flags; OFF: none); rows membership == the planned items (§5) in the planned order; per-item seeds == planned; the
  server-log slice (§6); power (§7); build drift (frozen record + repo state at entry == exit); `:8000` free after the chain.

## 3. The `invalidate` transport policy (P459)

New `run_config.TRANSPORT_POLICIES` member `invalidate` (P426 tg1 only; `abort_restart` stays the tg1 default):
- The first incomplete invocation of any cause (transport / connection error, timeout, worker or router identity change,
  served-config drift, hook `before`-stop) → `ChainAbort` with `chain.json.status = "invalid"` and the cause; no archive, no
  restart, no retry, no quarantine move (files stay where they are for the harvest).
- `resume_policy` irrelevant: an existing `chain.json` under `invalidate` refuses (a leg runs once).
- In-probe non-convergence (budget hit, turn cap, exec timeout, `client_inactivity`) is NOT a transport incident: it is a
  scored strict fail, as today.

  The exact argv per leg is generated by the sequencer and pinned in tests.

## 5. s2 item order (P461)

s2 runs each cell's items in REVERSE sorted order: the Python cell's in-load pilot (seed 2002's 5) first, reversed, then the
rest reversed; then Go reversed. Language order stays Python → Go (the in-load pilot stays Python, as in s1 / reload).
`schedules.tg1(order="reversed")` for s2 only; recorded in the schedule and `chain.json`; tests assert both orders and that
the probe receives `--items` in that order (the probe keeps argv order today).

## 6. Server-log slice: reconciliation and engagement (P463)

Slice = `logs/mlx_vlm.log` bytes after the leg's start offset (as Wave 1). Requests attributed by `session=`:
- `ses_*` = opencode; must equal the set of row `session_id`s; per item, completed requests == the row's
  `gate.requests_completed` (TBD from the rehearsal: `requests_observed` vs `gate.requests_completed`).
- `anon:*` = the A4 gate's requests; count == the A4 receipt's request count per load.
- started == completed, zero `Request failed`, every request `backend=cached_session`.
- ON: every `ses_*` request carries B1 `draft_kind=mtp` counters with 0 ≤ accepted ≤ proposed; rounds > 0 for every request
  with `generated_tokens ≥ 2` (TBD: confirm from the pilot that 1-token completions have rounds 0); per item and pooled
  acceptance recorded. OFF: no draft counters on any request.
- The per-item decode rate (plan §6 T2) and acceptance are computed by B6 from the same slice; B2 only persists it.

## 7. Speed / power validity (P462)

No second watcher: the chain's own 5-minute `WATCH` lines (progress, mean ETA vs prediction, convergence, token
distribution, watts / volts / battery) are the AGENTS.md daemon. The leg wrapper parses them at exit: any tick not 140 W /
28 V / battery > 20 %, an unparsable tick, or a gap > 2 × 300 s between ticks while an invocation runs → speed INVALID; plus
`pmset -g log` battery intervals over the leg window (Wave-1 rule). Quality survives a speed-invalid leg (labelled).
